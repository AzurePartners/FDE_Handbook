**一句话：** 最小权限是指每段代码、每个数据库用户、每个 API key 只拥有完成其工作所需的访问权限，不多给一点。

## 是什么

每个凭据，无论是数据库登录账号、API key 还是云服务角色，都带有一组权限：它能读什么、改什么、删什么。最小权限就是选择仍能让系统完成工作的最小权限集合，而不是“以防以后用得上”就给一大堆权限。

一个只读取汇率的服务，不应该持有一个还能删除记录的 key。即使这个 key 泄露，攻击者也只能做它被允许做的事。与之相对的是整个系统共用一个权限很大的凭据：方便是方便，但任何一处泄露都会让所有东西失守。

## FDE 为什么需要

AI 编程工具倾向于授予宽泛的权限，因为这样开发时更省事，比如给一个只需要读数据的组件配一个拥有完整读写权限的数据库用户。在客户那里，这种偷懒会让一个泄露的 key 变成对真实客户数据的完全访问。在新凭据上线之前，先确认它真正需要哪些权限。

## 核心概念

- **默认拒绝：** 从零权限开始，只添加工作所需的权限。
- **范围：** 把访问限制在实际用到的表、存储桶或端点上，而不是所有资源。
- **读与写：** 只读数据的组件，就给只读凭据。
- **限时访问：** 临时凭据或会过期的访问权限，优于永久有效的 key。
- **agent 权限：** AI 编程 agent（智能体）同样持有访问权限。以 Claude Code 为例，它的设置里可以配置允许和拒绝规则，比如拒绝 `Read(./.env)`。

## 常见误区

- **“现在多给点权限，省得以后再申请。”** 这同样会让这个凭据的每一次泄露后果更严重。收窄权限并不更难配置，只是需要更用心。
- **“最小权限只适用于人类用户账号。”** 它同样适用于服务账号、API key、代码和 AI agent。

## 典型面试题

<details>
<summary>“最小权限”是什么意思？请举个例子。</summary>

只给一段代码、一个用户或一个 key 它所需要的访问权限，不多给。一个只查询汇率的服务应该使用只能读的数据库凭据，而不是还能写入或删除的凭据。

</details>

<details>
<summary>AI 工具为一个只读数据的组件配置了拥有完整管理员权限的数据库用户，你会怎么做？</summary>

把它换成一个只读凭据，并把范围限定在该组件实际需要的表上。否则一旦 key 泄露，造成的破坏会远远超出这个组件本来需要的权限范围。

</details>
