**一句话：** 模型的一条回复可能以四种不同的方式失败（幻觉、格式漂移、指令冲突和上下文缺失），每一种都有各自的成因，也要在系统的不同部分修复。

## 是什么

客户常把好几种不同的问题都归到“AI 在编造内容”这一条下。模型是依据训练中形成的模式写出看似合理的下一个词，既不查资料，也不核对事实，所以一条回复可能内容出错，可能格式出错，可能听从了错误的指令，也可能建立在它从未收到的事实之上。

幻觉是指流畅、具体，却得不到现实或所提供来源支持的输出。设想一个从不留空的考生：如果答错和写“我不知道”都得零分，那么猜就是最优策略。OpenAI 的研究人员（Kalai 等人，2025）认为，训练和评测对模型的奖励方式与此如出一辙。

## FDE 为什么需要

一个 FDE 在为一家家具零售商试点客服助手时，听到的反馈是“AI 在编造内容”。日志里其实有四个缺陷：没有订单查询工具，却编造出一个物流单号；报出 30 天退货期，是因为 14 天的软包家具例外条款从未被检索到；系统提示词明明禁止承诺退款日期，却根据粘贴进来的一封邮件承诺了 3 天内退款；还有每 150 条回复里就有 1 条被 markdown 代码围栏包住，工单打标器直接把它静默丢弃了。

每个缺陷的修法都不一样，而涉及金额或政策时，提示词里加一句话永远不够：2024 年，加拿大的一个仲裁庭裁定 Air Canada 须为其聊天机器人说错的退款规则承担责任。

## 核心概念

### 四种失败模式

| 失败类型 | 症状 | 根因 | 修复位置 |
|---|---|---|---|
| 幻觉 | 自信地给出编造的政策、ID、日期或引用 | 做看似合理的猜测，没有查询 | 上下文中的可信事实，加代码检查 |
| 格式漂移 | 多出开场白、JSON 外面包着围栏、字段被改名、输出 `Refund Request` 而不是 `refund_request` | 格式只靠文字描述来要求；输出被截断；模型拒答 | Schema 约束的输出，加校验器 |
| 指令冲突 | 听从用户或某份文档，而不是系统提示词 | 指令自相矛盾；角色优先级是训练出来的，并非强制执行 | 写明优先规则，把硬性规则放进代码 |
| 上下文缺失 | 笼统或过时的答案，编造出的默认值 | 事实从未进入提示词（检索未命中、没有工具、对话历史被裁剪） | 上下文、检索和工具，外加“未找到”路径 |

这几行只是一种诊断视角，并不是标准分类，而且上下文缺失常常会演变成幻觉。有意的覆盖则是提示词注入（prompt injection）。

### 闭卷与基于来源

闭卷是指模型凭记忆作答，却把某个现实世界的事实答错；对策是把这个事实提供给它。基于来源（grounding）则是指模型拿到了来源文档，却与它们相矛盾、添油加醋或引错了出处。基于来源能减少幻觉，却不能消除：2024 年斯坦福的一项研究发现，基于检索的法律工具在 17% 到 33% 的查询上出现幻觉；Google 的研究人员（ICLR 2025）则发现，当检索到的上下文不够用时，强模型往往会答错，而不是拒答。

### 编造的 ID、日期和引用

罕见而任意的具体细节风险最大：它们没有规律可学。Anthropic 的可解释性研究（2025）发现，Claude 有一条默认的“无法回答”回路，而熟悉感会把它关掉，所以一个看着眼熟、其实并不了解的名字，就可能被模型编出事实。假的订单 ID 就像假钞：格式没错，账本上却没有记录。正则表达式（regex）会让它通过；只有查询权威数据源（system of record）才能抓住它。引用也是同样的失败方式：在 2023 年的 Mata v. Avianca 一案中，律师提交了一份引用六个案例的诉状，这些案例全是 ChatGPT 编造的，结果被罚款 5,000 美元。

### 自信的语气不说明任何问题

流畅而笃定的文风是从文本里学来的，并不能证明模型核对过什么。NIST 自己的定义里就写着“自信地陈述但错误或虚假的内容”，而研究发现，模型在给自己的答案打分时过于自信。

## 常见误区

- **“最新的模型已经解决了幻觉问题。”** 没有哪家供应商声称做到了零幻觉；2025 年，在 OpenAI 自家的 PersonQA 基准上，o3 和 o4-mini 的幻觉比 o1 还多。
- **“我直接问模型它确不确定就行了。”** 犯下这个错误的是同一个过程，回答这个问题的也是它。要对照来源验证，并且在代码里完成。
- **“temperature 设为 0 就能杜绝幻觉。”** 它提高的是一致性，而不是正确性：2025 年的一项研究中，43% 的编造软件包名在十次运行中每次都会出现。
- **“结构化输出能杜绝编造。”** Schema 约束的是结构，而不是真伪：合法的 JSON 里照样可以装着编造的订单 ID。

## 典型面试题

<details>
<summary>什么是幻觉？LLM 为什么会产生幻觉？</summary>

它是流畅、具体，却得不到现实或所提供来源支持的输出。模型在没有查询的情况下预测看似合理的文本，而只分对错的评分方式奖励的是猜测，不是“我不知道”。

</details>

<details>
<summary>闭卷幻觉与基于来源的幻觉有什么区别？</summary>

闭卷时，模型记错了某个现实世界的事实，所以要把这个事实提供给它。基于来源时，模型与给定的文档相矛盾或引错了文档，所以要求它给出引用，并用代码检查这些引用。

</details>

<details>
<summary>一个助手为并不存在的订单给出了物流单号。你会怎么修？</summary>

trace 里没有任何查询调用，说明上下文缺失变成了编造。要加一个只读查询工具、一条“未找到”的回复，再加一道代码检查，确保回复里的每个 ID 都来自这个工具。

</details>

<details>
<summary>只告诉模型不要编造，够吗？</summary>

值得加上，因为允许模型说“我不知道”确实有帮助，但这只是一种引导。对于价格、政策和 ID，要提供可信的事实，在代码里验证，把握不大的情况则转人工处理。

</details>
