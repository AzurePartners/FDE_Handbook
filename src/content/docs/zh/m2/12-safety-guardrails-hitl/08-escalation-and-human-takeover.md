**一句话：** 升级通道是一条设计好的路径，由代码检查触发，把对话从 AI 助手转给合适的人并附上摘要，此后助手保持沉默。

## 是什么

有些对话，助手不应该独自走完：证据不足、话题敏感、反复失败，或者用户想找真人。升级就是把对话转给人工团队。接管则是此后由员工负责这段对话，助手不再回复。

打个比方，医生的转诊信会写明：你是谁、哪里不舒服、已经试过什么。专科医生不用从零开始，你也不用把经过再讲一遍。

准确地说，一条通道有四个部分：触发条件、路由、交接摘要和接管状态。注意“handoff”这个词：在 OpenAI Agents SDK 里，它指把工作交给另一个 AI agent，而不是交给人。

## FDE 为什么需要

一所大学的学生支持助手，第一个月就收到三起投诉。一名学生三次要求“找真人”，每次得到的都是手册摘录，这就是美国消费者金融保护局所说的“恶性循环”（doom loop）。一名学生以健康问题为由申请额外的考试时间，得到的却是通用的延期政策，残障服务办公室始终没有收到消息。一起费用争议转到财务部门时，只带着一句“学生需要费用方面的帮助”，员工只好让学生把经过重新讲一遍。

这些问题都不需要更好的模型，只需要 FDE 把衔接环节搭好。（示例场景。）

## 核心概念

### 代码能检查的触发条件

| 触发条件 | 代码能看到的信号 |
|---|---|
| 证据不足 | 检索标记出来源无法支撑一个答案 |
| 敏感话题 | 政策分类器命中，不管模型听起来多有把握 |
| 反复失败 | 计数器触顶，比如同一个问题上失败了两次 |
| 用户要求找人 | “人工”或“真人”检测器命中；始终优先 |

表中刻意没有模型自评的置信度。Xiong 等人（ICLR 2024）发现，LLM 用文字表述自己的置信度时“往往过于自信”，而且所有方法在专业领域的知识上都表现吃力，这恰恰是客户所在的领域。阈值和话题清单在别处讲解（见相关页面）。

### 路由与交接摘要

按话题、紧急程度和语言做路由，并在承诺提供真人协助之前先确认员工是否在岗。冷转接会让用户重新解释一遍；暖转接则先把上下文发过去：

```json
{
  "student_id": "S-20417",
  "queue": "finance",
  "trigger": "user_requested_human",
  "recap": "对一笔滞纳金有异议；称已约定分期付款方案。",
  "transcript_url": "https://support.example.edu/t/8812"
}
```

身份、队列和触发条件由代码从会话中填入。只有摘要是模型写的；它可能出现幻觉，所以附上对话记录链接，方便员工核对。

### 接管：同一时间只有一个声音

给每段对话的存储记录加一个 `owner` 字段，并在每一条会调用模型的路径上检查它：

```python
def handle_message(conv, text):
    conv.save_user_message(text)
    if conv.owner != "assistant":     # "waiting" 或 "human"
        notify_staff(conv)            # 助手保持沉默
        return
    trigger = check_triggers(conv, text)
    if trigger:
        escalate(conv, trigger)       # 把 owner 设为 "waiting"
    else:
        reply_with_model(conv)
```

Google 的转人工文档描述了真人加入时虚拟 agent 变得“沉默”；它仍然可以为员工起草内部备注。要告诉用户谁将加入、大概要等多久，以及非工作时间的选项（创建工单，由邮件回复）。

### 升级日志形成闭环

记录每次升级的原因代码、话题、团队和结果，并每周与客户一起回顾。话题集中的地方，对内容负责人来说就是知识缺口；员工标记为“不需要”的案例，用来调整触发条件。Anthropic 的客服指南用“升级效率”（正确升级对比漏掉的升级）来衡量，并建议把目标定在 95% 或更高。

## 常见误区

- **“直接问模型有多大把握，低于 70% 就升级。”** 模型自述的置信度校准得很差。要依据代码能观测到的信号来触发。
- **“升级率越低，说明助手越好。”** 它可能掩盖漏掉的升级：那些需要真人、却一直留在机器人这里的用户。
- **“只要机器人足够好，提供真人就是可选项。”** 在 2024 年 Gartner 的一项调查中，60% 的客户担心 AI 会让联系真人变得更难；西班牙的第 10/2025 号法律则要求适用范围内的公司提供人工客服。

## 典型面试题

<details>
<summary>什么是升级通道？通常由什么触发？</summary>

一条设计好的路径，把对话连同上下文从助手送到合适的人工团队。常见的触发条件有：证据不足、敏感话题、反复失败和用户要求找人，这些都由代码检查，而不是靠模型的判断。

</details>

<details>
<summary>升级和拒答、人在回路审批有什么区别？</summary>

拒答用一个理由和下一步结束一次请求，没有人加入。审批把某一个操作（比如大额退款）暂停下来，等人确认后助手继续。升级则是把整段对话交给人。

</details>

<details>
<summary>你会怎么设计交接，让员工不必从零开始？</summary>

先确认员工是否在岗，再按话题、紧急程度和语言路由。附上由代码填写的字段（用户 ID、触发条件）、一段简短的模型摘要和对话记录链接。员工接受之后，用 owner 标记让助手保持沉默，并告诉用户大概要等多久。

</details>

<details>
<summary>接管期间，用户看到机器人的回复和员工的回复混在一起。哪里出了问题？</summary>

某条路径，比如重试、webhook 或第二个 worker，在没有检查接管状态的情况下调用了模型。每段对话只保留一个 owner 字段，在每次面向用户的回复之前检查它，并加一个在接管期间发送消息的测试。

</details>
