**一句话：** 大语言模型（LLM）是一个用海量文本训练出来的程序，它预测下一小段文本，所以是凭学到的模式一段一段地写出答案，而不是去查找事实。

## 是什么

手机输入法会根据你已经打出的内容推荐下一个词；LLM 做的是同一件事，只是规模大得多。它给每一个可能的下一个 token（一小段文本，对 Claude 来说约合 3.5 个英文字符）打分，从中选出一个追加到文本末尾，然后循环往复。这个选择通常是采样得到的，而不是每次都取得分最高的那个，所以同一个提示词可能返回不同的措辞。

预训练在海量文本上进行，确定模型的权重，也就是（几乎总是）transformer 网络内部学到的数值。后训练（用精选示例做微调，再加上基于人类反馈的强化学习，即 reinforcement learning from human feedback）把这个预测器变成能遵循指令的助手。

训练在发布前只进行一次。推理（inference）则是在每次请求中运行这个冻结的模型；用户输入的任何内容都不会改变权重。模型的知识停在某个截止时间，它也没有内置的查询或事实核查能力：最新数据或私有数据只能通过请求或工具送到模型面前。

## FDE 为什么需要

一家保险经纪公司的助手在面向消费者的聊天应用里表现很好，通过 API 调用时却出了问题。被问到某份保单是否仍然有效时，它只能猜：聊天应用会通过自己的系统提示词悄悄加入今天的日期，而直接调用 API 时没有这一步。被问到这家经纪公司的新产品“Fleet Plus”（在知识截止时间之后推出，也从未公开）时，它却流畅地介绍了更早的类似产品。一位经理改用最高档位并打开深度思考：回复更慢，账单更高，错误的答案还是一样。

缺的是数据，而不是智力。FDE 在每个请求里放入今天的日期和相关的保单文本（之后改用[检索](../09-rag-knowledge-bases/01-retrieval-augmented-generation.md)和[工具](../10-tool-calling-deterministic-logic/01-tool-calling.md)自动完成），并把深度思考留给多步骤的任务。

## 核心概念

### 知识截止时间

Anthropic 为每个模型列出两个日期：可靠知识截止时间，以及范围更宽的训练数据截止时间。截至 2026 年 9 月仍是当前版本的 Claude Haiku 4.5，其可靠知识截止时间是 2025 年 2 月。截止时间要看模型供应商的模型页面；模型会误报自己的截止时间。

### 模型系列与档位

模型供应商把一个系列按规模分成不同档位，在能力与速度、价格之间做取舍。截至 2026 年 9 月，Anthropic 的产品线从 Claude Fable 5.1（能力最强）起，经过 Opus 5.5（官方推荐的起点）和 Sonnet 5.5，到 Haiku 4.5（最快）。Google 的 Gemini 有 Pro、Flash 和 Flash-Lite；OpenAI 的每一代 GPT 都有多种规格；Microsoft Foundry 提供 Azure OpenAI 和 Claude 模型。产品线每月都在变，所以要从配置里读取模型 ID，并用你自己的提示词测试来选择档位。

### 推理模型

推理模型在回答之前，会先在草稿纸上演算。草稿纸是要花钱的：在所有主要供应商那里，思考 token 即使被隐藏或只返回摘要，也按输出计费。思考还会推迟第一个可见字词出现的时间。Anthropic 只返回思考摘要，或者什么也不返回。在 Claude Opus 5.5 和 Fable 5.1 上，思考始终开启，由推理强度设置来控制思考多少。

思维链提示（chain-of-thought，2022 年）则是让普通模型“一步一步地思考”，这样推理过程就出现在可见的回复里，需要你的代码把它分离出来。推理模型由 OpenAI 的 o1 在 2024 年 9 月推广开来，它们是通过强化学习训练出来的，会先推理再作答。

## 常见误区

- **“模型像搜索引擎一样去查答案。”** 它是根据学到的模式做预测；最新数据或私有数据只能通过请求或工具送达。
- **“它会从我们用户的对话中学习。”** 调用模型不会重新训练它。只有换成新的模型版本或有意做微调，行为才会改变。
- **“它不过是高级一点的自动补全，所以不会做规划。”** 预测是接口，而不是能力的上限：Anthropic 2025 年 3 月的可解释性研究发现，Claude 会先选好韵脚，再朝着它写出整行诗。
- **“思考文本展示了模型是怎么做出决定的。”** 在 Anthropic 2025 年 4 月的一项研究中，Claude 3.7 Sonnet 实际用到了某条提示线索，却只在 25% 的情况下提到了它。思考文本是一种信号，而不是审计日志。

## 典型面试题

<details>
<summary>什么是 LLM？什么是下一个 token 预测？</summary>

一个用海量文本训练、根据前面的全部内容预测下一个 token 的模型，它一次追加一个 token，循环往复。它生成的是看似合理的文本，而不是去查找什么。

</details>

<details>
<summary>训练和推理有什么区别？为什么这很重要？</summary>

训练在发布前一次性确定权重；推理则是每个请求都运行这个冻结的模型。所以它不会在使用中学会客户的政策，最新数据或私有数据必须放进请求，或者通过工具获取。

</details>

<details>
<summary>客户的助手信心十足地错误介绍了上个季度的新产品。为什么会这样？</summary>

该产品晚于知识截止时间，所以模型是照着类似产品编出了一段看似合理的描述。我会在每个请求里提供最新的产品文档，或者通过查询工具提供，并为近期的产品补充测试用例。

</details>

<details>
<summary>换成推理模型后账单翻了一倍，回答却没有变长。为什么？</summary>

隐藏的思考 token 按输出计费。我会先在用量数据里确认这一点，再降低推理强度，或者把简单请求分流到更快的档位，并在真实用例上检查质量。

</details>
