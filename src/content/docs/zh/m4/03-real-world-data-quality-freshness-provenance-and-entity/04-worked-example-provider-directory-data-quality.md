**一句话：** 医疗机构名录（医生的姓名、专科和联系方式）集中展现了现实中的每一种数据问题，而把它清洗一遍（去重、专科校验、联系方式新鲜度、人工确认），能让抽象的数据质量概念变得具体。

## 是什么

**医疗机构名录**列出医疗机构及其专科和联系方式。它是一份典型的脏数据集：同一位医生出现在多个系统里（**重复**），专科录入得不一致或有误（**校验**），电话和地址会随着人员搬迁而**过期**，不同来源的记录还会**冲突**。清洗它意味着：通过实体解析对医疗机构**去重**，对照受控词表**校验**专科，按阈值检查**联系方式的新鲜度**，并把不确定的情况送去**人工确认**。本页是一个示例详解，在一项贴近实际的任务上把第 3 课的概念串联起来。

## FDE 为什么需要

医疗和金融是 FDE 的核心领域，名录清洗是一个贴近实际的首个项目。看清这些概念如何组合（用实体解析去重，用新鲜度 gate 管联系方式，用校验管专科，用 HITL 处理不确定的合并），能让你做好应对真实数据清理的准备，而不是把每个概念孤立地看。它也说明了所谓“AI”工作，有多大一部分其实是细致的数据工程。

## 核心概念

- **去重：** 对出现在多个系统里的医疗机构做实体解析，合并成一条记录。
- **专科校验：** 对照受控词表检查；标记无效或有歧义的条目。
- **联系方式新鲜度：** 对电话和地址套用新鲜度 gate；刷新或标记过期的。
- **冲突解决：** 系统之间不一致时，为每个字段指定一个事实来源。
- **人工确认：** 低置信度的合并和未解决的冲突交给人处理。

```
医疗机构（3 个系统）-> 按 NPI / 名称+地址匹配 -> 去重
  -> 对照分类体系校验专科 -> 标记未知项
  -> 对照 12 个月的 gate 检查联系方式的年龄 -> 标记过期项
  -> 冲突 / 低置信度 -> 人工审核队列
```

## 常见误区

- **“名录只是简单的参考数据。”** 它一次性集中了重复、过期、冲突和校验问题。
- **“把整个清洗过程都自动化。”** 不确定的合并和冲突需要人工确认，在出错代价高昂的医疗领域尤其如此。
- **“校验就是检查格式。”** 校验还包括对照受控词表和现实情况检查取值，而不只是看格式。

## 典型面试题

<details>
<summary>讲讲你会怎么清洗一份医疗机构名录。</summary>

先用实体解析对各源系统里的医疗机构去重：依据稳定的键（比如 NPI）以及名称和地址匹配；对照受控的分类体系校验每个专科，标记未知项；对联系方式套用新鲜度 gate，标记或刷新过期的；用每个字段各自的事实来源解决字段冲突；低置信度的合并和未解决的冲突送进人工审核队列，而不是靠猜。

</details>

<details>
<summary>人在回路（HITL）应该用在这个任务的哪些环节？</summary>

用在不确定且风险高的决定上，也就是低置信度的实体匹配和未解决的冲突：在这些地方，自动化给出错误答案（把两位不同的医生合并，或者列错专科）会造成真实的伤害。高置信度、低风险的清洗可以自动化；有歧义的情况交给人工确认。

</details>
