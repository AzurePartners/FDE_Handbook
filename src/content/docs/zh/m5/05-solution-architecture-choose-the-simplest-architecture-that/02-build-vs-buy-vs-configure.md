title: 自建、采购还是配置
row: M5-L5.2

**一句话：** 对方案的每个部分，决定是自建、采购现成产品，还是配置现有平台；并且知道什么时候该用 Puffo/Pavlov 这类平台，什么时候该用代码库、MCP 或定制服务，从而只把自建的精力花在能创造独特价值的地方。

## 是什么

每个组件有三种选择。**自建：** 自己定制开发，适合针对客户问题的、有差异化的核心部分。**采购：** 对通用能力（认证、监控、向量库、LLM 本身），直接用现成的产品或服务。**配置：** 使用并设置现有平台，而不是从零开始写代码，比如基于 **Puffo/Pavlov**（持久型 agent 平台）来搭建，而不是自己写定制服务；或者把 **MCP** 接到现有工具上，而不是自己做一个连接器。关键功夫在于逐个组件做决定：把定制开发集中在有差异化的部分，其余的采购或配置。

## FDE 为什么需要

在一个 FDE 项目里，时间是稀缺资源。自建通用基础设施，或者重复实现平台已经具备的功能，既白白耗掉时间，又带不来客户价值，还会留下长期的维护负担。为 agent 层配置 Puffo/Pavlov，只在上面自建客户专属的逻辑，通常比整套定制开发快得多，也更好维护。凡事条件反射般自己动手的 FDE，交付很慢；把通用部分交给采购或配置的 FDE，交付更快，需要维护的东西也更少。

## 核心概念

- **自建：** 有差异化的、客户专属的核心部分。
- **采购：** 专业团队能解决得更好的通用能力（LLM、认证、监控、向量库）。
- **配置：** 设置现有平台（Puffo/Pavlov），或接入 MCP，而不是从零写代码。
- **平台与代码库：** 平台擅长的事就用平台；只有必要时才退到定制代码。
- **总拥有成本（TCO）：** 自建就意味着永远要维护，要把这笔账算进去。

## 常见误区

- **“自己做，掌控力更强。”** 但这同时也留下长期的维护负担；只在有差异化的地方自建。
- **“配置平台算不上真正的工程。”** 用好 Puffo/Pavlov，再在上面搭出合适的定制层，这恰恰就是本职工作，而且更快。
- **“采购或配置就意味着没法定制。”** 你可以把配置好的平台、采购的通用能力，加上针对差异化核心的定制代码组合起来用。

## 典型面试题

<details>
<summary>你怎么决定自建、采购还是配置？</summary>

逐个组件来定。针对客户问题、有差异化的核心，我自建；专业团队做得更好的通用能力（LLM、认证、监控、向量库），我采购；对现有平台，比如 agent 层用 Puffo/Pavlov，或者工具接入用 MCP，我配置，而不是从零写代码。目的是只把定制开发的精力花在能创造独特价值的地方，并把需要维护的东西降到最少。

</details>

<details>
<summary>什么时候用 Puffo/Pavlov，什么时候用定制代码库？</summary>

我会把 Puffo/Pavlov 用在它本来就擅长的事情上，比如持久型 agent 的生命周期、状态和编排，对这些做配置；只为平台没有覆盖的客户专属逻辑写定制代码。只有平台确实满足不了某个真实需求时，才值得退到完全定制的代码库，因为定制意味着要构建和维护的东西更多。

</details>
