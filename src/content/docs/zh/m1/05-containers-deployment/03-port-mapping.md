**一句话：** 容器的端口对外是关闭的，除非你显式地把它连接到宿主机的某个端口上。

## 是什么

容器运行在自己隔离的网络空间里。即使里面的应用监听 80 端口，只要这个端口没有发布（publish）到宿主机，外部就访问不到。`docker run -p 8000:80 my-app` 做的就是这件事：左边的 `8000` 是 **宿主机端口**，也就是外部连接的端口；右边的 `80` 是 **容器端口**，也就是容器内应用监听的端口。发往 `localhost:8000` 的请求会被转发到容器内的 `80` 端口。

Dockerfile 里的 `EXPOSE 80` 只是声明应用使用哪个端口，并不会发布任何端口；真正的发布发生在运行时，靠 `-p` 完成。

## FDE 为什么需要

“访问不到应用”是刚接触容器时最常见的问题之一，而且几乎总是端口问题，不是代码 bug。能看懂 `-p 8000:80`、分得清哪边是哪边的 FDE，几秒钟就能定位原因，不用对着代码瞎猜。

## 核心概念

### 两个常见错误

- **容器内的应用监听 `127.0.0.1`，而不是 `0.0.0.0`。** `127.0.0.1` 只接受来自同一网络命名空间内部的连接，而宿主机不在这个命名空间里。应用必须绑定到 `0.0.0.0`，才能接收经由已发布端口转发进来的连接。
- **顺序写反，或者映射了错误的容器端口。** `-p 8000:80` 的格式是“宿主机:容器”，不是反过来。如果应用实际监听的是 8000 而不是 80，`-p 8000:80` 就会把流量发到一个没有任何程序监听的端口上，连接失败的表现和端口关闭一样。

## 常见误区

- **“Dockerfile 里的 EXPOSE 会发布端口。”** 它只是声明。发布要在运行时用 `-p` 完成。
- **“宿主机端口和容器端口必须一致。”** 可以不同。`-p 3000:8000` 完全合法：连接宿主机的 `3000`，Docker 会转发到容器内的 `8000`。

## 典型面试题

<details>
<summary>在 `docker run -p 8000:80 my-app` 中，两个数字分别是什么意思？</summary>

`8000` 是宿主机端口，也就是从外部连接的端口。`80` 是容器内应用实际监听的端口。

</details>

<details>
<summary>容器在运行，端口映射看起来也正确，但应用还是访问不到。你会检查什么？</summary>

检查容器内的应用监听的是 `0.0.0.0` 还是 `127.0.0.1`。绑定到 `127.0.0.1` 只接受来自容器内部的连接，已发布的端口就没有可以转发的目标。

</details>
