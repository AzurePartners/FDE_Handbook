**一句话：** 研究台的后续阶段会补上这一版有意省略的内容；而它的核心模式，即掌管所有数字的确定性后端、负责解读和提出异议的 agent、发布检查以及按实际结果打分，可以迁移到其他高风险的决策支持问题。

## PRD 推迟了什么

| 后续阶段 | 要回答的问题 |
|---|---|
| 实习结束后继续前向交易 | 前向结果在比三周更长的时间里是否依然成立 |
| 纯规则对照组合 | agent 相比纯规则到底增加了多少价值，这一阶段无法衡量 |
| 定时每周任务和自动用量跟踪 | 研究台能否在无人启动的情况下运行，成本是多少 |
| 更多股票和更多信号 | 方法能否扩展到固定股票池之外 |
| 持牌的电话会议记录和分析师预期 | 更丰富的证据能否提升专家 agent 的挑战质量 |
| 更强的 Risk agent 隔离 | 面对更有针对性的干扰时，异议是否依然独立 |

实盘交易被明确定为一个独立的、受监管的项目，不属于本项目。

纯规则对照组合值得特别关注。在它出现之前，诚实的说法是：已发布的判断就是规则的判断，只是被 agent 调得更保守，而没人知道这种保守是否有帮助。好的 FDE 会把这句话写进结果报告，而不是任由读者以为 agent 增加了价值。

## 这一模式在其他领域

去掉股票，这个模式是通用的。它适合任何这样的问题：决策依赖数字，数字随时间变化，而决策事后可以对照结果来评判：

| 领域 | 确定性后端掌管 | Agent 负责解读 | 独立异议 | 对照打分 |
|---|---|---|---|---|
| 信贷审查 | 财务比率、政策阈值 | 经营背景、管理层质量 | 看不到分析师材料的信贷风险审核者 | 之后的违约和逾期 |
| 保险核保 | 损失历史、定价模型输出 | 风险叙述、异常敞口 | 对盲审档案给出意见的第二位核保人 | 理赔经验 |
| 采购 | 投标价格、交付记录、合同条款 | 供应商匹配度、定性风险 | 为第二名辩护的审核者 | 交付表现 |
| 销售预测 | 销售管线阶段、历史转化率 | 具体交易的信号 | 审阅每笔承诺交易的怀疑者 | 实际成交收入 |

每一行都适用本课的四个问题：当时我们知道什么？每个数字从哪里来？谁站在了反方？结果如何？

## 典型面试题

<details>
<summary>你怎么证明 agent 相比规则增加了价值？</summary>

在相同成本和时点下，让一个纯规则组合与已发布组合并行运行，在同一前向期间比较。同时衡量 Risk agent 对埋入反证的识别率，以及在干净用例上的误报率。在此之前，把 agent 的作用报告为未知。

</details>

<details>
<summary>客户希望这个研究台下真实订单，你怎么回答？</summary>

实盘交易是另一个受监管的项目，在券商集成、控制、合规和监督方面有自己的要求。这个研究台按设计就没有下单路径，加一条下单路径不是对这个系统的扩展，而是一个新系统。

</details>
