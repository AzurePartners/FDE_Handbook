**一句话：** Trade Recommendation Desk 是 [Puffo](https://chat.puffo.ai) space 中由六个 AI agent 组成的团队，每周审阅一个固定的 10 只美股池；每个判断都由后端策略引擎基于两个市场信号生成，agent 负责审阅、挑战和解释，全程不涉及真实资金。

## 业务场景

一位投资经理希望获得研究支持：每周对一组股票给出观点，并随时回答关于其中任意一只的问题。AI 工具可以很快给出买卖意见，问题是没人能核查它们。PRD 列出了常见的失败方式：

- 数字没有出处，或者取自错误的时间段；
- 回测用到了当时还不存在的信息；
- 规则在历史数据上反复调参直到好看，遇到新数据就失效；
- 结果忽略了交易成本或大盘本身的涨跌；
- 判断发出后从未与后来的实际情况对照。

研究台的回答是：**这些失败靠系统控制来防止，而不是靠 prompt 指令。**

这是 Azure Partners 的内部实习项目。不使用真实资金，不下真实订单，没有外部用户。每个判断都是假设性的，不构成投资建议。

## 为什么这是最复杂的原型

之前每个案例都只有一个难点，这个案例同时具备全部难点：

| 特征 | 为什么在这里很难 |
|---|---|
| 数字 | 每个判断都依赖价格和财报数字。自己敲数字的 agent 可能敲错或编造。 |
| 时间 | 今天正确的数字，在决策当天可能还不存在。用了它就是前视偏差（lookahead bias）。 |
| 过拟合 | 规则变体足够多时，总有一个会碰巧在历史数据上表现很好。 |
| 异议 | 有用的研究台需要一个不受他人引导、专门唱反调的声音。 |
| 评估 | 输出是预测，所以可以、也必须和实际结果对照打分。 |

## 团队

| Agent | 职责 |
|---|---|
| Desk Lead | 主频道中唯一的 agent。启动每次运行、给专家分派任务、发布结果。 |
| Technical | 审阅趋势和价格证据。 |
| Volume | 检查成交量是否支持价格变动。 |
| News | 审阅截止时间之前发布的新闻和公告。 |
| Fundamentals | 审阅已报告的业绩、盈利意外和公司指引。 |
| Risk | 在看到其他 agent 结论之前，站在反方论证。 |

每个专家 agent 与 Desk Lead 共享一个私有频道，不与其他任何人共享。

## 一个判断是怎么产生的

1. 策略引擎为每只股票给出初始观点：BUY、SELL 或 NO TRADE。
2. Desk Lead 把任务分派给五个专家 agent。
3. 四个信号 agent 各自返回带证据的观点。
4. Risk agent 返回自己的评估。
5. 规则引擎把所有内容合成为最终判断和信心等级（conviction）。
6. 发布服务检查判断，发布它或附带原因地拦截它。
7. 模拟组合在下一个收盘价执行新判断。
8. 每个判断在复核日之后打分。

**Agent 可以降低信心等级或把判断改为 NO TRADE，但永远不能提高。** 判断由规则产生，agent 负责解读和挑战。

## Syllabus 的重点在设计中的位置

| Syllabus 重点 | 在设计中的体现 |
|---|---|
| 时点数据（point-in-time） | 不可变的数据快照，通过只返回运行截止时刻已可得行的视图读取 |
| 来源证据 | 每个数值都有 evidence ID，链接到其公告或供应商记录、期间和时间 |
| 异议 | 一个隔离的 Risk agent，其首次评估带哈希存储，不可编辑 |
| 置信度 | 由引擎强度和 agent 支持度决定的信心等级表，可被风险规则下调 |
| 数据新鲜度 | 每次运行都有截止时间；发布检查拦截任何晚于截止时间的证据 |
| 工具成本 | 每个 agent 每次唤醒最多 10 次工具调用；一次运行消耗 11 次 agent 唤醒 |
| 记忆 | 运行状态由后端的 run manager 保存，不需要任何 agent 记住 |
| 可追溯的结论 | 前端的来源抽屉，可以打开任何已发布数字的出处 |

## 是研究，不是交易

Syllabus 要求在决策支持和自动交易之间划清界限。研究台在代码层面划了这条线：没有券商连接、没有下单路径，如果出现下单代码，仓库扫描会让构建失败。公告数据来自免费公开的 SEC EDGAR，日线价格来自一家持牌数据供应商。

## 常见误区

- **"买什么是 agent 决定的。"** 初始观点由策略引擎生成，最终判断由规则引擎设定。agent 只能让它更保守。
- **"agent 越多，判断越好。"** 四个信号 agent 的存在是为了从不同角度挑战引擎，BUY 或 SELL 需要其中至少三个不反对。数量服务于一条规则。
- **"回测好看就证明了策略。"** 只有在冻结规则上只跑一次的 holdout，以及前向模拟交易，才是在未调参数据上的证据。

## 典型面试题

<details>
<summary>为什么 agent 只能降低判断，而不能提高？</summary>

提高判断意味着依据经过测试的规则之外的东西行动，等于把未经测试的判断重新引入了已验证的部分。降低永远是安全的：最坏的结果是错过机会，而不是持有未经验证的仓位。这种不对称让 agent 可以增加谨慎，又不会破坏回测的有效性。

</details>

<details>
<summary>这个研究台和自动交易系统有什么区别？</summary>

研究台发布研究判断，并在模拟组合中跟随执行。代码中没有券商连接或下单路径，一旦出现，仓库扫描会让构建失败。PRD 把实盘交易描述为一个独立的、受监管的项目。

</details>
