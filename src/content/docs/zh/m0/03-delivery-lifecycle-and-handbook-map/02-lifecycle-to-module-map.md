**一句话：** FDE 生命周期的每个阶段都对应本手册的一个具体部分，所以模块零之后的 44 节课是一张能力地图，而不是一串主题。

## 是什么

| 阶段 | 在哪里培养这项能力 | 在那里学什么 |
|---|---|---|
| Qualify、Discover | 模块五第 2–3 课 | Discovery 访谈、stakeholder 地图、现状/目标流程 |
| Define | 模块五第 4–5 课 | 范围、PRD 与 SOW、验收标准、选择最简单可行的架构 |
| Build | 模块一至模块三 | 软件系统（M1）、AI 应用工程（M2）、Agent 工程（M3） |
| Build（与客户一起） | 模块五第 6 课 | Demo、反馈与变更请求 |
| Integrate | 模块四第 1–3 课 | API 与 MCP connector、认证与权限、真实世界的数据 |
| Evaluate | 模块二第 5 课；模块三第 6 课 | AI 应用的评测；Agent 的评测、追踪与调试 |
| Deploy | 模块四第 4–5 课 | 可靠性、成本与规模；部署、CI/CD 与可观测性 |
| Adopt、Handoff、Productize | 模块五第 7 课 | 试点、业务价值、移交与产品化 |

有三个模块覆盖的是整个闭环，而不是单个阶段：

- **模块六**把生命周期应用到四个复杂度递增的用例原型上（客服 RAG 应用、内容工作流、医疗服务方调研与触达、多 Agent 研究台）。
- **模块七**是实战项目：你亲自走完整个生命周期，从 Discovery 到 Handoff。
- **模块八**把这些工作变成 FDE 面试中的证据。

## FDE 为什么需要

它回答了每个新读者都会问的问题："我为什么要学这个？"当模块四的某一课看起来纯粹是基础设施时，这张地图告诉你它服务于客户项目的哪个阶段。它也帮你做规划：如果你最弱的责任是 Adoption，你就知道该优先读哪一课。

## 核心概念

### 模块一到模块四就是 Production 责任

八个内容模块里有四个服务于 Production。这反映了现实：在企业 AI 里，让东西在真实环境中安全运行，是大部分工程投入所在。

### 模块五是 FDE 特有技能所在

Discovery、范围界定、变更管理、采用和产品化，是 FDE 区别于优秀工程师的地方。模块五覆盖生命周期的两端。

### 评测出现两次是有意为之

评测单个 AI 应用（模块二）和评测多步骤的 Agent（模块三）需要不同的方法，两者都服务于 Evaluate 阶段。

## 常见误区

- **"模块必须严格按顺序读。"** 顺序是为初学者排的。有经验的读者可以直接跳到自己需要的阶段；见[手册阅读路径](./03-handbook-reading-paths.md)。
- **"模块五是软技能模块。"** 它包含具体的产物（stakeholder 地图、PRD、验收标准、试点指标），评判标准和代码一样严格。
