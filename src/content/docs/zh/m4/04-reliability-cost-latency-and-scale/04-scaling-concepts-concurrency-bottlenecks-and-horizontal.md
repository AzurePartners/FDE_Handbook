**一句话：** 扩展说的是许多用户同时涌入系统时会发生什么，关键在于判断力：能看出系统会在哪里成为瓶颈（队列深度、数据库或 API 限流），并且知道通常的答案是水平扩展和队列，而不是靠硬扛，也不需要你自己搭一个巨大的集群。

## 是什么

在负载之下，一个对单个用户工作正常的系统可能会垮掉。负载均衡、水平扩展和数据库瓶颈这些通用的扩展概念，已在模块一中讲过（[负载均衡与水平扩展](../../m1/06-reliability-scale/09-load-balancing-and-horizontal-scaling.md)及相邻页面）；这里的重点是 **AI 功能** 会在哪里受限。关键概念有：**并发**（同一时刻有许多请求在处理中）、**队列深度**（等待处理的工作量，队列越积越长，说明你跟不上了）、**瓶颈**（限制吞吐量的、最慢的共享资源，通常是数据库或有限流的外部 API），以及 **水平扩展**（增加更多实例来应对更多负载，相对的是垂直扩展，即换一台更大的单机）。对 AI 功能来说，瓶颈往往是模型 API 的限流或数据库，而不是你自己的算力。FDE 的核心能力在于判断：预判负载会在哪里受限，并恰当地选用队列和水平扩展，而不是为了搭基础设施而搭基础设施。

## FDE 为什么需要

只用一个用户演示过的功能，到了客户的规模上可能会崩，而失败通常出在一个可预见的瓶颈上。一个 FDE 必须预判“500 个并发用户会发生什么？”，并让设计给出的答案是“请求会排队，系统跟得上”，而不是“系统垮掉”。你很少需要搭建大型集群，但必须能推断系统会在哪里受限，并用上标准对策。

## 核心概念

- **并发：** 同时在处理中的请求；系统必须扛得住突发流量。
- **队列深度：** 积压量的大小；深度持续增长，说明吞吐量低于请求到达速率。
- **瓶颈：** 起限制作用的共享资源（数据库、有限流的 API）；要优化它，或对它做扩展。
- **水平扩展：** 在负载均衡器后面放更多实例；通常优于换一台更大的机器。
- **背压（backpressure）与队列：** 吸收突发流量、平滑负载，而不是把瓶颈压垮。
- **重判断，而非搭集群：** 找出受限之处，运用标准对策；别过度设计。

## 常见误区

- **“演示时能用，所以能扩展。”** 一个用户会掩盖那些只有在并发下才会出现的瓶颈。
- **“换一台更大的机器就行了。”** 垂直扩展有上限；水平扩展加队列通常能支撑到更大的规模。
- **“瓶颈在我们自己的算力上。”** 对 AI 功能来说，瓶颈往往是模型 API 的限流或数据库；要扩展或缓解真正受限的那一环。

## 典型面试题

<details>
<summary>一个功能对单个用户没问题，但你预计会有 500 个并发用户，你会检查什么？</summary>

先看它会在哪里出现瓶颈：模型 API 的限流、数据库，或者任何共享的外部依赖，以及工作队列会积压到多深。我会加上队列来吸收突发流量，对受限的资源做扩展（增加实例做水平扩展、升级到更高的 API 档位、扩充数据库容量），并做负载测试，确认吞吐量跟得上，而不是队列无限增长。

</details>

<details>
<summary>水平扩展和垂直扩展有什么区别？</summary>

垂直扩展是换一台更大的单机，简单，但有上限，而且是单点故障。水平扩展是在负载均衡器后面增加更多实例，能扩展到更大的规模，还多了冗余。对大多数生产负载，通常的答案是水平扩展加队列，真正要做的工作是缓解实际的瓶颈。

</details>
