**一句话：** 拒答是请求越界时设计好的回复，兜底是某个环节失败时设计好的回复；两者都会给出简短的理由和下一步。

## 是什么

助手没有给出答案，要么是不该答（拒答：请求违反了与客户约定的边界），要么是答不了（兜底：模型过载、某个查询不可用，或者输出无法使用）。无论哪种情况，用户都会读到一些内容，所以要把它设计好。

打个比方，药剂师会说：“没有处方不行，不过你的医生可以开一张。”一句简短的理由，不说教，并指出下一步该怎么走。

模型供应商也用“fallback”指把被拒绝的请求改投到另一个模型上重试，但宕机仍然会波及你的应用。这里的兜底指的是告诉用户什么、给用户提供什么选择。

## FDE 为什么需要

一家车险公司的理赔进度机器人，上线第一周就以三种方式失败。超范围的租车问题只得到一句“这个问题我帮不了你”，于是客户换个说法再问，然后打电话进来。理赔查询超时的时候，模型编造了一句“你的理赔应该很快就会结算”。一个安全分类器在流式输出过程中把答案截断了；屏幕上留下半句话再加一条拒答，而下一条消息会失败，因为被拒答的那一轮仍留在对话历史里。

错误仪表盘上什么异常都没有：每个响应都是 HTTP 200。（示例场景。）

## 核心概念

### 回复阶梯

| 梯级 | 适用情形 | 示例 |
|---|---|---|
| 回答 | 在范围内，且有数据支撑 | “9 月 3 日已获批准。” |
| 附带提醒的回答 | 某个明确的不确定性会改变用户该怎么做 | “今天的付款可能还没显示。” |
| 澄清问题 | 问题含糊，猜错的代价高 | “是 4471 号理赔还是 4478 号？” |
| 升级 | 应该由人接手（见相关页面） | “正在为你转接理赔专员。” |
| 拒答 | 超出约定的边界 | 见下方模板 |

选择限制最少、同时又不越界的那个梯级。

### 拒答的措辞

```text
差：作为一个 AI 模型，我无权提供保障范围方面的建议。
    咨询专业人士是很重要的。
好：这里我没法回答保障范围方面的问题。你的保单文件在 [link]，
    或者我可以帮你转接人工客服。
```

OpenAI 的 Model Spec 推荐采用“Safe Complete”（简短说明原因，然后给出仍然安全的帮助），并要求拒答“绝不应说教”。Anthropic 的 constitution 要求 Claude 始终说明自己帮不了什么（哪怕不说原因），好让用户可以去别处求助，并在有生命危险时指引用户联系紧急救援服务。涉及欺诈或安全检查时，理由要保持笼统。

### 兜底消息

如果重试之后模型仍然过载、某个查询不可用，或者输出修复失败，就发送一条固定的消息，绝不能让模型凭记忆作答：“我现在连不上理赔系统，所以没法告诉你进度。你的理赔编号已保存。请稍后再试，或拨打 [number]。”

参照 GOV.UK 的“服务出现问题”页面模式：用平实的话（别出现“500”）、说明用户输入的内容怎么样了，并提供另一条途径。在降级模式下提供缓存的答案，则以[缓存](../../m1/06-reliability-scale/08-caching.md)为基础。

### 检测与记录日志

拒答有三种形式：成功响应上的标记（Anthropic 的 `stop_reason` 为 `"refusal"`，OpenAI 的 `refusal` 字段或 `content_filter`，Gemini 的 `SAFETY`）、异常（OpenAI Agents SDK 的护栏 tripwire），或者一段普通文字。把每一种都映射到一个模板：

```python
if msg.stop_reason == "refusal":     # HTTP 200，不是错误
    log_event("refusal", msg._request_id, msg.stop_details.category)
    history.pop()                    # 丢弃被拒答的这一轮
    return TEMPLATES["refusal"]      # 取代已输出的部分文本
```

不要去解析 Anthropic 返回的、内容不稳定的 `explanation` 文本。把拒答和兜底各自记为独立的事件（比率见相关页面）。

## 常见误区

- **“拿不准的时候，拒答总是最安全的选择。”** 死胡同会让用户换着说法重问、想办法骗过机器人，或者直接打电话进来；Anthropic 的 constitution 指出，不提供帮助绝不是想当然的“安全”。
- **“好的拒答要详细解释政策。”** 一句简短的理由加上下一步就够了，再多就成了说教。
- **“查询失败了，也让模型照样回答。”** 它听起来同样笃定，却常常是错的。
- **“错误监控能发现拒答。”** 多数拒答是以成功响应或普通文字的形式出现的。

## 典型面试题

<details>
<summary>拒答和兜底有什么区别？</summary>

拒答是有意拒绝一个越界的请求。兜底应对的是失败：过载、工具超时、无效输出。两者都需要给出理由和下一步。我会分开记录日志：拒答交给政策审核，兜底交给 bug 修复。

</details>

<details>
<summary>什么时候你会提出澄清问题，而不是附带提醒地作答？</summary>

请求含糊、猜错代价又高的时候。如果我能回答，只是有一处不确定性会改变用户的行动，就用附带提醒的回答。

</details>

<details>
<summary>对话进行到一半，向量检索超时了。用户应该看到什么？</summary>

绝不能是模型凭记忆给出的回答。重试失败后，展示一条固定消息：检索暂时不可用，请稍后再试或联系服务台。同时记录一条兜底事件。

</details>

<details>
<summary>聊天界面显示了半截回答，后面跟着“这个问题我帮不了你”，之后的下一条消息又失败了。为什么？</summary>

分类器中断了流式输出，界面把拒答追加在了已输出的部分文本后面，而被拒答的那一轮还留在对话历史里。用模板替换掉部分文本，丢弃这一轮，并记录这次拒答。

</details>
