**一句话：** [Puffo](https://chat.puffo.ai) Marketing Studio MVP PRD（工程评审草案，2026 年 8 月 27 日）定义了一个单客户、本地优先的系统：四个 agent 生成 HTML 营销素材，不懂技术的营销人员无需接触代码即可编辑和导出。

> **原始文档：** *Puffo Marketing Studio MVP Product Requirements Document*，Azure Partners。本页是阅读指南：这份 PRD 决定了什么、哪些地方值得注意。完整需求请阅读原文。

## 这份 PRD 决定了什么

| 章节 | 决定 |
|---|---|
| 概述 | 一个客户、一个 Puffo Space、本地优先。编辑器运行在客户电脑上，通过 localhost 或局域网访问。不做 SaaS、云数据库或公网访问。 |
| 问题 | 三类摩擦：营销人员不该需要开发工具；小改动不该需要调用模型；HTML 转 PPTX 会损坏设计。 |
| 目标 | 多个营销人员、四个 agent、三种素材类型（海报、落地页、幻灯片）、浏览器内编辑、HTML 是唯一可编辑母版、自动保存、手动发布。 |
| 非目标 | 不做 PPTX、PDF、自动发布、公网访问、多租户 SaaS、实时协同编辑、自由布局、演讲者备注、审批角色模型、RAG、完整版本树。 |
| 用户 | 营销人员（提需求、编辑、导出、标记完成）和开发者/管理员（安装、维护、处理故障）。访问限制依靠局域网边界加一个无法猜到的 job URL。 |
| Agents | Marketing Lead、Campaign Copywriter、Fact & Compliance Reviewer、Visual Designer。 |
| 编辑器 | 独立浏览器标签页；打开即可编辑文字；版式锁定；文字超长时在模板限制内缩小字号，到下限后给出提示；图片和二维码通过占位符替换；六个按钮的工具栏；防抖自动保存；带心跳的单编辑者锁。 |
| 数据模型 | 每个 job 一个文件夹：`brief.md`、`material.html`、`review.md`、`state.json`、AI 初稿和最终确认版的快照、导出文件。 |
| 验收 | 12 项检查，包括：Reviewer 拦截错误的课程事实；第二个会话只读；海报 PNG 与浏览器预览一致；不产出 PPTX 或 PDF，不自动发布任何内容。 |

## 可衡量的成功

成功指标都是测试者可以核对的数字：本地环境下文字编辑渲染不超过 200 毫秒；最后一次编辑后 1 秒内完成自动保存，并显示 `Saving…`、`Saved` 或 `Save failed`；PNG 导出在字体、颜色和版式上与预览一致；任何含未确认事实或硬性合规违规的素材，在到达营销人员之前就被 Reviewer 拦截。

## 值得注意的地方

**非目标清单比目标清单还长。** 这是一个自律的 MVP 的标志。每个非目标都是相关方很可能会提出的需求，写下来，免得有人误做。

**只有一个母版格式，就消灭了一整类 bug。** HTML 是唯一可编辑母版的决定（ADR-002）意味着预览和导出来自同一个文件，不存在会产生偏差的第二份副本。去掉 PPTX 不只是少了一个功能，也去掉了造成视觉缺陷的转换步骤。

**架构决策记录在 PRD 里，因为它们决定了范围。** 五条 ADR（独立浏览器编辑器、HTML 作为唯一母版、本地优先、锁定版式、单编辑者）各附一行理由。它们是带有技术后果的产品选择，所以在工程开始前就定下来。

**PRD 写明了它不做哪些决定。** 第 16 节列出不影响产品审批的工程选择：前端技术栈、HTML 转 PNG 的渲染器、锁的持久化、SVG 上传策略、Puffo 如何打开本地链接、agent profile 如何同步到 Puffo。这等于告诉工程师，他们的自由从哪里开始。

**失败状态本身就是需求，而不是事后补充。** 第 12 节覆盖了缺失事实、Claude 登录过期、编辑器服务离线、自动保存失败、不支持的上传、导出失败、缺少字体和过期锁。贯穿始终的规则是：绝不报告没有发生的成功。

**现有仓库保留，而不是替换。** 课程事实和合规政策原地不动。PRD 在旁边新增 `agents/`、`puffo/`、`editor/` 和 `templates/`，并禁止复制事实。

## 常见误区

- **"本地优先就是没做完。"** 这是有意划定的阶段边界（ADR-003）。先验证生成和编辑体验，再加安全、身份和托管。
- **"锁定版式是用户会讨厌的限制。"** 锁定版式保护品牌一致性，去掉了编辑器的大部分复杂度，同时覆盖了营销人员最常做的修改（ADR-004）。
- **"单编辑者锁太原始。"** 对小团队的本地使用来说，实时协同和冲突合并的成本远远高于收益（ADR-005）。

## 典型面试题

<details>
<summary>有相关方要求"只是作为一个选项"加上 PPTX 导出。你怎么用这份 PRD 回答？</summary>

指向问题陈述和 ADR-002。PPTX 转换正是产品要解决的三个问题之一，因为它会损坏设计。把它作为选项加回来，就又有了第二个母版格式，以及两者之间的偏差。如果需求真实存在，它属于后续阶段，并且要带上自己的保真度要求。

</details>

<details>
<summary>为什么保存模型只在 AI 初稿和最终确认时创建快照？</summary>

因为每敲一次键就存一个版本只会制造没人看的噪音，还会让 Git 塞满无意义的提交。真正重要的两个快照是 AI 产出的版本和人工确认的版本。当前草稿原地保存，撤销历史只需在浏览器会话内有效。

</details>

<details>
<summary>你会先给工程师看这份 PRD 的哪一部分？为什么？</summary>

非目标清单和第 16 节一起看。非目标告诉他们不要做什么，第 16 节告诉他们哪些技术决定由他们来做。有了这两部分，其余需求就是在一个清晰空间内的约束。

</details>
