**一句话：** 一个 FDE 的能力横跨八个维度：Systems、AI、Agents、Integration、Production、Discovery、Communication 和 Domain，不同的 FDE 岗位对它们的权重不同，所以了解这个模型，能帮你看清“好”是什么样子，以及该往哪里成长。

## 是什么

这个角色涉及面很广，**能力模型** 把它拆成八个维度：

- **Systems：** 软件 / 系统基础（模块一）。
- **AI：** LLM 应用工程（模块二）。
- **Agents：** 智能体式模式与编排（模块三）。
- **Integration：** 对接企业系统、认证与数据（模块四）。
- **Production：** 可靠性、部署、可观测性（模块四）。
- **Discovery：** 找到真正的问题、明确需求（模块五）。
- **Communication：** 利益相关方沟通、演示、写作（模块五）。
- **Domain：** 对客户所在领域的了解（金融、医疗）。

每个维度都能说清“好”是什么样子；不同的 FDE 岗位又侧重不同的维度（数据密集的项目偏重 Integration / Production；从零开始的顾问式项目偏重 Discovery / Communication）。

## FDE 为什么需要

这个模型既是这个角色的地图，也是自我提升的工具：它展示完整的范围（让你不会把编码强误当成 FDE 强），让你如实评估自己的长处和短板，也帮你理解某个项目或岗位最看重什么。它还是整本手册的主线：每个模块都在培养特定的维度。

## 核心概念

| 维度 | 大致覆盖于 |
| --- | --- |
| Systems | 模块一 |
| AI | 模块二 |
| Agents | 模块三 |
| Integration | 模块四 |
| Production | 模块四 |
| Discovery | 模块五 |
| Communication | 模块五 |
| Domain | 在工作中学习 / 客户所在领域 |

- **每个维度的“好”：** 有明确描述的标准，而不是凭感觉。
- **岗位权重不同：** 要弄清一个项目侧重什么。

## 常见误区

- **“只要代码写得强，就是强 FDE。”** 编码只占其中一两个维度；Discovery、Communication 和 Domain 同样重要。
- **“每个 FDE 都要把八个维度全部拉满。”** 不同岗位的权重不同；你应该朝着自己的工作所需要的组合去发展。
- **“领域知识可有可无。”** 在金融、医疗领域，它往往起决定作用；它是一个明确列出的维度。

## 典型面试题

<details>
<summary>FDE 能力模型有哪些维度？</summary>

Systems、AI、Agents、Integration、Production、Discovery、Communication 和 Domain。前五个偏技术（从基础一直到生产集成），后三个是咨询与背景类的能力：找到真正的问题、与利益相关方沟通、了解客户所在的领域。不同的 FDE 岗位对它们的权重不同。

</details>

<details>
<summary>为什么这个模型对你自己的成长很重要？</summary>

因为它描绘了这个角色的全貌，让我不会把编码强误当成 FDE 强。我可以据此如实评估自己在八个维度上的长处和短板，并朝着某个项目所要求的组合去成长，比如进入新行业时，把精力投到 Domain 和 Discovery 上，而不只是继续加深 Systems。

</details>
