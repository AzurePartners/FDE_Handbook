**一句话：** 一份参考 PRD，描述一个辅导 / 客服助手：基于教育机构自己的文档回答学生和客户的问题，为每个答案标注出处段落，拒答文档没有覆盖的问题，并把敏感情况交给人处理。

> **教学参考。** 这份 PRD 是为 handbook 撰写的，格式沿用 [PRD：交易研究台](../04-trading-desk/03-prd.md)。它不是某个真实项目的文档。其中的数字是真实团队需要与客户一起确定的目标值。

## 1. 概述

课程客服助手在聊天界面中回答教育机构的学生、家长和潜在客户的问题。每个答案都来自机构自己的知识库：课程资料、FAQ、报名与退款政策，以及客服人员以往给出的回答。助手不对任何账户执行任何操作。

答案的所有权仍在客服人员手里。助手改变的只是谁先找到答案。

## 2. 问题

答案是存在的，但很难找到。学生每周问同样的问题。客服人员凭记忆和旧文档粘贴回复，所以不同人的答案不一样，还会偏离现行政策。新员工分不清哪份文档是最新的。一个凭自身训练数据而不是凭文档作答的 AI 助手会让情况更糟：流畅、自信、错误。

助手用系统控制来防止这些问题，而不是靠 prompt 指令。

## 3. 用户

| 用户 | 做什么 |
|---|---|
| 学生或客户 | 提问，阅读答案及其出处 |
| 客服人员 | 接收升级转来的问题，附带对话记录和检索到的段落 |
| 知识负责人 | 维护文档、审批变更、下线过期文档 |
| 工程师 | 搭建并运行助手 |

## 4. 产品规则

这些规则适用于所有地方，永远不能违反。

1. 每个答案都引用它所依据的段落，每条引用都指向本次回答实际检索到的段落。
2. 助手从不陈述检索段落中没有的事实。
3. 知识库没有覆盖的问题，回复"未覆盖"并给出找人的途径。
4. 涉及具体个人账户、成绩、退款或投诉的问题，一律转给人。
5. 已被取代的文档永远不可被检索到。
6. 助手不对任何业务系统执行操作。
7. 历史工单中的个人信息在导入前删除。

## 5. 范围

范围内：当前课程的课程资料、FAQ、政策和清洗后的历史问答；聊天界面；引用；拒答；升级转到客服收件箱；知识更新通道；评测集和评测报告。

第一版不做：对账户、报名或付款的操作；多 agent 编排；语音；机构两种工作语言之外的语言；基于学生记录的个性化。

## 6. 运作方式

1. 用户提问。
2. 助手从当前版本的知识库中检索候选段落。
3. 策略代码决定路径：升级（规则 4）、未覆盖（没有段落达到阈值）或回答。
4. 模型只依据检索到的段落撰写答案，并附引用。
5. 代码在答案展示之前，逐条核对引用是否在检索集合内。
6. 升级会创建一张客服工单，附上问题、对话和检索到的段落。
7. 每个答案都记录知识库版本和段落 ID。

## 7. 需求

**知识。** 每份文档都有负责人、生效日期和版本。新版本发布时取代旧版本。历史工单在导入前清除个人信息。

**答案。** 用用户的语言，平实表达，附可打开的引用。文档之间有分歧时，助手如实说明并同时引用。

**拒答与升级。** 升级话题清单是配置，不是 prompt 文本。"未覆盖"的回复要写明去哪里求助。

**新鲜度。** 政策变更在发布后一个工作日内到达助手。过期文档下线后不可能再被引用。

**隐私。** 助手从不索要或存储账户凭据。对话按声明的期限保留，之后删除。

## 8. 成功指标

始终为真：每条引用都能对应到检索到的段落；已下线的文档永远不会被引用；每个升级话题都会转给人。

在评测集上衡量，阈值在调优前与客户商定：答案正确率不低于 90%；引用准确率不低于 95%；对超范围问题的拒答准确率不低于 95%；升级准确率不低于 95%。

运行中衡量：无需人工介入即解决的客服问题占比；答案中位延迟低于 5 秒；每个答案的负面反馈率。

## 9. 验收标准

1. 当前 FAQ 能回答的问题，引用的是当前 FAQ。
2. 关于已废止政策的问题，引用当前版本，绝不引用已废止的版本。
3. 超范围问题产生"未覆盖"回复和找人途径。
4. 涉及具体账户的退款问题会创建工单，并附上对话和段落。
5. 引用不在检索集合内的答案，在展示前被拦截。
6. 评测集在每次改动后运行，结果被保存。
7. 测试工单导出中埋入的个人信息不会出现在索引里。
8. 负责人发布的文档在一个工作日内可被回答。

## 10. 后续阶段

查询用户自己课程状态和订单的读工具；创建工单、调班等写工具，每个都带确认和审计；第二种语言；基于学生记录的个性化。
