**一句话：** 端到端的咨询公司同样可以把一个项目从 discovery 一路做到生产，所以区别不在谁写代码；FDE 在本公司的产品之上交付，并把学到的东西回流到产品，让服务下一个客户的成本更低。

## 是什么

"咨询"涵盖的工作范围很广：

- **战略与管理咨询**产出分析、建议和路线图，很少写代码。
- **技术咨询与系统集成**（Accenture、Deloitte、Capgemini、IBM Consulting、Thoughtworks 等大公司，以及许多小公司）端到端地设计、开发、集成、测试、部署并经常运维生产系统，背后是庞大的工程团队和托管服务合同。

所以"咨询写 PPT，FDE 写代码"这种常见说法，对行业里很大一部分是错的。一个技术咨询团队可以做 discovery、设计架构、写生产代码、和十几个企业系统集成，并把它推进到生产。无论 FDE 和这类工作的区别是什么，都不是代码。

## FDE 为什么需要

你会经常和咨询顾问一起工作：客户的系统集成商往往负责周边系统，很多供应商也通过咨询合作伙伴交付。面试中你也会被问到你的角色有什么不同。精确的回答会赢得尊重；轻慢的回答（"咨询只会提建议"）暴露的是你不了解这个市场。

## 核心概念

### 真正不同的地方

| | 战略咨询 | 技术咨询 / SI | FDE |
|---|---|---|---|
| 写生产代码 | 很少 | 是 | 是 |
| 对生产结果负责 | 否 | 经常是，以合同约定为准 | 是 |
| 建立在本公司产品之上 | 否 | 通常不是；跨多家供应商的平台工作 | 是 |
| 可复用经验去哪里 | 框架和方法论 | 公司的方法论、加速器和交付资产 | 产品本身 |
| 收入随什么增长 | 人数 | 人数（即使是固定价格或按结果的合同） | 产品使用量 |
| 典型的结束状态 | 交付建议 | 移交给客户，或作为托管服务运行 | 移交给客户，通用部分被产品吸收 |

### 与产品的关系是锚点

系统集成商确实会构建可复用资产：加速器、参考架构、模板。区别在于这些复用沉淀在哪里、怎么带来回报。在咨询公司，它提升的是公司的交付能力，业务仍然靠增加人手来增长。在 FDE 所在的公司，它进入一个每个客户都能得到的产品，所以服务每个客户所需的人力应该随时间下降。这就是[角色判据](./02-role-tests.md)里说的"可复用的产品杠杆"。

### FDE 团队什么时候变成了咨询

一个 FDE 组织如果没有任何东西回流到产品，员工按人力利用率考核，每个项目都从零开始，那它在经济上就是软件公司里的一家咨询公司。McGrew 在 Y Combinator 的 Lightcone 播客里正好讨论了这个风险：只有产品团队把一线做出来的东西通用化，FDE 模式才成立。

### 两者经常一起工作

供应商常常通过 SI 合作伙伴交付。一种常见模式是：SI 负责客户更大的项目群和周边集成；供应商的 FDE 负责让产品在其中真正起作用，并把经验带回来。

## 常见误区

- **"咨询顾问只产出 PPT。"** 战略咨询大多如此；技术咨询和集成商会构建并运行生产系统。
- **"为客户做的任何定制工作都是咨询。"** 只有当什么都没回流到产品时，定制工作才像咨询。
- **"FDE 就是换了名字的咨询。"** 对没有产品回流机制的 FDE 团队来说，实际上是的。对有回流机制的团队，经济结构完全不同。

## 典型面试题

<details>
<summary>Accenture 的团队也能为这个客户做同样的系统，为什么还需要 FDE？</summary>

他们能做，有些项目里也确实会做。FDE 多出来的是与产品的关系：对产品内部的深入了解，在客户需要通用能力时修改产品的能力，以及让这个客户的经验降低下一次部署成本的通道。实践中两者常常并肩工作，由 SI 负责更大的项目群。

</details>

<details>
<summary>你怎么判断一个 FDE 组织是否已经滑向咨询？</summary>

看一线做的东西有没有进入产品，新部署的成本是否随时间下降，以及 FDE 是按人力利用率还是按结果被考核。

</details>
