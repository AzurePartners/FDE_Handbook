**一句话：** 状态码是每个 HTTP 响应开头的三位数字，让你一眼看出请求是成功了、失败了，还是需要再做点什么才能完成。

## 是什么

每个 HTTP 响应都以一个状态码开头。它是了解发生了什么的最快信号，比读响应 body 或查日志都快。状态码按首位数字分成五个区间：1xx 表示“还在处理”，2xx 表示“成功了”，3xx 表示“去别处找”，4xx 表示“客户端做了服务器不接受的事”，5xx 表示“服务器自己出错了”。

你不需要背下每一个状态码。你需要一眼认出它属于哪个区间，并记住经常出现的那几个：200、400、401、403、404、429 和 500 就能覆盖大多数实际情况。状态码由服务器根据后端的处理结果来选定，它应该是一个可靠的摘要，前端或脚本不用解析 body 就能据此行动。

## FDE 为什么需要

在支持电话里，状态码是缩小 bug 范围最快的手段。用户报告“应用坏了”时，失败请求的状态码会告诉你该先看哪一边。400 或 404 通常指向客户端发送的内容。401 或 403 指向认证或权限。429 指向限流，而不是 bug。500 或 502 指向服务器本身或它依赖的某个服务。在客户旁观的现场调试中，先看状态码能实实在在地节省时间。

## 核心概念

### 五个区间

| 区间 | 含义 | 什么时候会看到 |
|---|---|---|
| 1xx | 信息性，请求已收到，仍在处理 | 日常 API 工作中很少见 |
| 2xx | 成功 | 请求按预期完成 |
| 3xx | 重定向 | 去别处找：通常是跳转到一个新 URL；304 表示用你本地缓存的副本 |
| 4xx | 客户端错误 | 请求本身有问题 |
| 5xx | 服务器错误 | 服务器在处理一个有效请求时失败了 |

### 值得记住编号的状态码

| 状态码 | 名称 | 含义 |
|---|---|---|
| 200 | OK | 请求成功 |
| 201 | Created | 成功创建了一个新资源 |
| 204 | No Content | 请求成功，但没有内容需要返回 |
| 301 / 302 | Moved | 资源已永久或临时移到新的 URL |
| 400 | Bad Request | 请求格式错误或缺少必需数据 |
| 401 | Unauthorized | 请求需要有效凭证，但凭证缺失或错误 |
| 403 | Forbidden | 服务器拒绝该请求；重新登录也没用 |
| 404 | Not Found | 请求的资源不存在 |
| 408 | Request Timeout | 服务器等不到请求的剩余部分，放弃了 |
| 429 | Too Many Requests | 客户端触发了限流 |
| 500 | Internal Server Error | 服务器在处理时遇到了意外错误 |
| 502 | Bad Gateway | 充当中间人的服务器从另一台服务器收到了无效响应 |
| 503 | Service Unavailable | 服务器暂时无法处理请求，通常是负载过高或停机维护 |

### 把状态码对应到实际场景

假设一个返回城市天气的 API：请求 `/weather?city=` 却没给城市，应该返回 `400`，因为客户端发送的请求不完整。请求一个不存在的城市，应该返回 `404`。如果后端调用天气服务商时对方挂了，后端应该返回 `502`，因为此时它是作为客户端在调用一个出故障的上游服务器。

```
GET /weather?city= HTTP/1.1
Host: api.example.com

HTTP/1.1 400 Bad Request
Content-Type: application/json

{"error": "city is required"}
```

## 常见误区

- **“404 就意味着整个页面都坏了。”** 404 的意思是所请求的那个具体资源没找到。应用的其他部分，甚至同一页面上的其他请求，都可能完全正常。
- **“500 错误总是客户端发了坏数据造成的。”** 500 专门表示服务器意外失败。如果客户端发了坏数据，写得好的后端应该捕获它并返回 400，而不是崩成 500。
- **“状态码 200 就说明数据是对的。”** 200 只表示服务器成功处理了请求。body 里仍可能是空结果，或者前端用不了的数据。
- **“3xx 是错误。”** 3xx 是重定向指令，不是失败。大多数 HTTP 客户端会自动跟随，用户根本察觉不到。

## 典型面试题

<details>
<summary>HTTP 状态码的五个区间大致分别表示什么？</summary>

1xx 是信息性的，表示仍在处理。2xx 表示成功。3xx 表示重定向到另一个 URL。4xx 表示客户端发送了服务器不接受的内容。5xx 表示服务器在处理一个本身有效的请求时失败了。

</details>

<details>
<summary>401 和 403 有什么区别？</summary>

401 表示请求缺少有效凭证，服务器不知道是谁在请求，或者凭证是错的。403 表示服务器知道是谁在请求，但这个身份无权执行该操作。

</details>

<details>
<summary>客户的系统调用你的 API 时收到 502。这说明了什么？</summary>

502 表示充当中间人的服务器，从它所依赖的另一台服务器那里收到了无效响应。检查你的后端对其上游依赖的调用是否成功，因为故障很可能还在更上游一环。

</details>

<details>
<summary>你在日志里看到一个 429。这是 bug 吗？</summary>

不一定。429 通常意味着触发了有意设置的限流，目的往往是防止服务器被压垮。正确的处理通常是等一段时间再重试，而不是把它当成代码缺陷去修。

</details>
