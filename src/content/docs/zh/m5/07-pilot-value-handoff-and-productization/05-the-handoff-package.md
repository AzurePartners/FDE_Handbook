**一句话：** 交接包是客户团队在没有你的情况下运行这个方案所需要的一切：安装配置、运维、权限、输入 / 输出、常见失败、重启与兜底流程，以及已知局限；你离开之后，你的工作能否延续，取决于它。

## 是什么

**交接** 是把所有权转给客户的团队。**交接包** 要记录：**安装配置**（怎样安装、配置它）、**运维**（怎样日常运行和监控它）、**权限**（它需要哪些访问权限，由谁管理）、**输入 / 输出**（它消耗什么、产出什么）、**常见失败**（通常会出什么问题、怎么修，即 runbook）、**重启 / 兜底流程**（怎样恢复，或安全地降级运行），以及**已知局限**（它不做什么，免得有人意外）。它是一次知识转移，最好在项目期间就逐步建立，并让客户团队参与其中，而不是在最后丢过去一堆文档。

## FDE 为什么需要

只有你一个人懂的方案，你一走就无法维护，会坏掉，你交付的价值也随之化为乌有。交接包让工作成果得以延续，而它常常被跳过，因为它没有构建那么令人兴奋，这也正是把它做好才能让人看出一个 FDE 是否专业的原因。它既保护客户（他们能把它运行起来），也保护你的声誉（它一直能用）。

## 核心概念

- **安装配置与运维：** 安装、配置、运行和监控。
- **权限：** 需要哪些访问权限，由谁负责。
- **输入 / 输出：** 它接收什么、产出什么。
- **常见失败（runbook）：** 典型问题及修复办法。
- **重启 / 兜底：** 恢复，或安全降级。
- **已知局限：** 一份明确的清单，避免出人意料。
- **知识转移：** 构建期间就让他们的团队参与；别在最后把文档一丢了事。

## 常见误区

- **“交接就是最后把文档发邮件过去。”** 它是一次有意安排的知识转移：文档、runbook，以及全程让他们的团队参与。
- **“代码写得干净，就不需要 runbook。”** 运维人员需要的是运行和修复它，而不是读源码；runbook 就是为此而写的。
- **“只要能跑，交接可有可无。”** 没有交接，你一走方案就无法维护，价值也就白费了。

## 典型面试题

<details>
<summary>一份好的交接包里有什么？</summary>

安装配置和运维说明，所需的权限及管理人，输入和输出，一份列出常见失败及修复办法的 runbook，重启和兜底流程，以及一份明确的已知局限清单。而且它是一次知识转移，最好在构建期间就让客户团队参与，而不只是最后丢过去一堆文档。

</details>

<details>
<summary>为什么交接常常做得很差？为什么它很重要？</summary>

它不如构建那么令人兴奋，又容易在最后仓促应付，所以常常被跳过。它之所以重要，是因为只有你一个人懂的方案，你一走就无法维护，会坏掉，交付的价值也随之被毁。有意识地做好交接，包括 runbook、文档，以及让他们的团队参与，才能让工作成果延续，也是专业 FDE 的标志。

</details>
