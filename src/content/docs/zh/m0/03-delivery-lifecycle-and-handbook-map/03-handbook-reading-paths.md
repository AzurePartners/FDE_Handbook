**一句话：** 读者根据自己的背景决定每个模块读到多深（Know、Use、Build 或 Design），跳过已经掌握的内容；模块零和模块七的实战项目对所有人都是必修的。

## 是什么

本手册的写法让没有软件背景的人也能从头读到尾。但大多数读者不需要这样读。阅读路径是一份计划：根据你已经掌握的东西，决定读哪些模块、读到多深。

### 四个深度等级

| 等级 | 你能…… | 例子（模块四，认证） |
|---|---|---|
| **Know（了解）** | 解释这个概念，在对话中认出它 | 解释认证（authentication）和授权（authorization）的区别 |
| **Use（会用）** | 正确使用现有的工具和配置 | 为一个 Agent 配置 API key 和只读角色 |
| **Build（能做）** | 在一个可运行的系统里自己实现它 | 为一个工具实现 OAuth 流程和按用户的权限 |
| **Design（会设计）** | 在多种方案之间选择，并为客户说清取舍 | 为多租户部署设计权限模型，并在安全评审面前为它辩护 |

## FDE 为什么需要

FDE 的准备面很广，时间有限。没有路径的话，初学者会淹没在模块一的细节里，有经验的工程师会跳过模块五，而那恰恰是他们最需要的模块。

## 核心概念

### 建议的起步路径

| 背景 | 通常最需要 | 通常可以读得轻一些 |
|---|---|---|
| 金融、医疗或市场营销的领域专家 | 模块一至三到 Use，模块五到 Build | 模块四到 Know 至 Use |
| 计算机专业学生或初级工程师 | 模块二、三、五 | 自查后，模块一的部分内容 |
| 后端或全栈工程师 | 模块二、三、五 | 模块一的大部分 |
| AI 工程师 | 模块四、五；模块三里的持久化和多 Agent 部分 | 模块二的大部分 |
| 咨询顾问或解决方案工程师 | 模块一至三（编程与系统素养） | 模块五的部分内容，但实战项目仍是必修 |
| 资深全栈 + AI 工程师 | 模块五和模块六的四个原型 | 模块一至二；直接进入实战项目 |

这些是默认建议，不是先修要求。对照每个模块的课程学习目标自查，跳过你已经能证明自己掌握的内容。

### 所有人必修

模块零，因为手册其余部分都使用它的术语；以及模块七的实战项目，因为完整做一遍项目是展示整个闭环的唯一方式。

### 每一页是怎么组织的

每个知识点页面结构相同：一句话定义、是什么、FDE 为什么需要、核心概念、常见误区、附参考答案的典型面试题、延伸阅读和相关页面。复习时先读一句话定义和常见误区；遇到新主题就读完整页。

## 常见误区

- **"有经验的工程师可以直接跳到面试模块。"** 模块五和实战项目考察的能力，单靠工程经验是练不出来的。
- **"专业之外的东西达到 Know 就够了。"** FDE 要跨整个系统工作。凡是你在客户环境里会碰到的东西，至少要达到 Use。
