**一句话：** 依赖是你的项目所依赖的、由别人编写的代码；依赖风险则是指这些代码存在已知安全问题、而你自己从未审查过的可能性。

## 是什么

几乎没有项目是完全从零写起的。一个 Python 项目可能用 `pip` 引入十几个包，一个 JavaScript 项目可能通过 `npm` 拉进来几百个包，每个包都会把自己的代码，以及它自己的依赖，带进你的项目。你的代码引入的每个包都不是你写的，而且说实话，你也从没完整读过。其中有些已发布的版本存在已知漏洞，也就是已经被发现并公开记录、但在你安装的那个版本里还没修复的安全问题。

依赖扫描工具会把你已安装的包和一个已知漏洞数据库进行比对，报告哪些包受影响，以及哪个版本修复了问题：

```
pip-audit          # 检查已安装的 Python 包是否存在已知漏洞
npm audit           # 检查 Node 项目锁定的依赖是否存在已知漏洞
```

两者报告的内容结构相同：受影响的包、发现的漏洞，以及修复它的版本。两个工具都不审查代码本身，它们只是把版本号和已知问题列表做比对。

## FDE 为什么需要

AI 编程工具推荐一个包，和它推荐一个函数名的方式一样：看它在见过的代码里出现得多不多，完全不知道这个包的当前版本有没有已知问题。另外，新的漏洞会不断在原本干净的现有包中被发现，所以项目刚开始时安全的依赖，到部署时可能已经有了已知问题。在临近部署时运行扫描，而不只是在搭建项目时跑一次，才能发现项目开始以来新出现的问题。

## 核心概念

### 什么时候运行扫描

在部署前运行，而不只是在初始搭建时运行一次，因为即使你的代码和依赖没有变化，扫描所比对的漏洞数据库也在随时间变化。很多团队还会在每个 pull request 上自动运行扫描，让新引入的包或新出现漏洞的包在合并之前就被发现。

### 流行度不代表安全

一个下载量上百万的包，某个特定版本照样可能有已知漏洞。扫描工具是把版本号和已公开问题的数据库做比对，而不是看一个包用的人多不多、口碑好不好，因为口碑说明不了某个具体版本的情况。

## 常见误区

- **“下载量上百万的包自然是安全的。”** 流行度不是安全保证。被广泛使用的包里也经常出现已知漏洞，这正是扫描工具检查具体版本、而不看口碑的原因。
- **“在项目搭建时跑一次扫描就够了。”** 新漏洞会不断在现有包中被发现。搭建时干净的依赖，到部署时可能已经有了已知问题。
- **“AI 工具不会推荐有漏洞的包。”** AI 推荐包的依据是它们在见过的代码里出现的频率，并没有实时对照漏洞数据库检查。这项检查是一个独立的步骤，仍然需要你自己去做。

## 典型面试题

<details>
<summary>为什么要在部署前运行 pip-audit 或 npm audit，而不只是在搭建项目时运行一次？</summary>

新漏洞会不断在现有包中被发现，所以搭建时干净的依赖，到部署时可能已经有了已知问题。临近部署时扫描，能发现项目开始以来新出现的问题。

</details>

<details>
<summary>依赖扫描工具实际检查什么？不检查什么？</summary>

它把已安装的包版本和一个已知、已公开漏洞的数据库进行比对，报告哪些包受影响、哪个版本能修复。它不会读取或审查包的实际代码，所以未知的、尚未公开的问题不会被发现。

</details>

<details>
<summary>扫描工具标记出你的项目依赖的一个包有漏洞，你会怎么做？</summary>

先看有没有更新的版本修复了这个问题，如果升级是安全的，就升级过去。如果还没有修复版本，就评估在你的使用方式下，有漏洞的代码路径是否真的会被执行到，并考虑临时的规避方案或换一个替代包。

</details>
