**一句话：** CI/CD 是把代码从提交一路送到生产环境的自动化流程：构建、测试、部署，出了问题就回滚；FDE 需要理解并用好这个流程，而不是手工搭建复杂的流水线。

## 是什么

**Continuous Integration（CI，持续集成）** 会在每次变更时自动构建并测试代码，及早发现改动弄坏了什么。**Continuous Delivery/Deployment（CD，持续交付/持续部署）** 会自动把通过测试的代码推向生产环境，或直接推入生产环境。核心的发布流程是：**构建**（编译/打包）、**测试**（运行自动化检查）、**部署**（推送到某个环境）和 **回滚**（新版本出问题时，迅速恢复到上一个版本）。你不需要从零搭建复杂的流水线，大多数平台都自带 CI/CD；但你必须理解这个流程，这样才能安全地发布，而且至关重要的是，在需要时能够回滚。

## FDE 为什么需要

把变更部署到客户的环境里，意味着要在不破坏现有功能的前提下发布改动。一套带自动化测试、能正常运转的 CI/CD 流程，能在回归问题到达用户之前就发现它们；万一有问题漏了过去，快速回滚就是你的安全网。理解这些的 FDE 发布时有底气，出问题也能迅速恢复；而手工部署、没有回滚预案的人，会把一个小 bug 变成一场宕机。

## 核心概念

- **CI：** 每次变更都自动构建 + 测试；及早发现改动弄坏了什么。
- **CD：** 让通过测试的变更自动走向生产环境，乃至直接进入生产环境。
- **环境：** 开发 → 预发布 → 生产；上生产之前先测试。
- **回滚：** 迅速恢复到最近一次已知正常的版本；在需要之前就规划好。
- **使用平台自带的 CI/CD：** 配置它，而不是手工搭建；目标是安全、可重复的发布。

```
提交 -> [构建] -> [测试] -> [部署到预发布] -> [部署到生产]
                                \-- 失败？ --> 回滚到最近一次正常的版本
```

## 常见误区

- **“CI/CD 就是搭建复杂的流水线。”** 多数情况下你只是在配置平台现成的流水线；理解这个流程，比搭建基础设施更重要。
- **“测试通过了，就不需要回滚。”** 测试总会漏掉一些东西；能快速回滚才是必不可少的安全网。
- **“直接部署到生产环境。”** 先部署到预发布环境并测试；生产环境不是用来发现问题的地方。

## 典型面试题

<details>
<summary>讲一遍基本的发布流程。</summary>

每次变更，CI 都会构建并运行自动化测试。测试通过后，CD 先把它部署到预发布环境做验证，再部署到生产环境。如果新版本在生产环境里表现异常，就立即回滚到最近一次已知正常的版本。重点是可重复、经过测试的发布，加上一条快速的回滚路径，而不是手工搭建的流水线。

</details>

<details>
<summary>为什么回滚能力如此重要？</summary>

因为测试永远不可能抓住所有问题，而在客户的生产环境里，一次糟糕的部署会造成真实的影响。快速且演练过的回滚，能把“我们发布了一个 bug”变成一次短暂的波动，而不是一场漫长的宕机，它也是让你放心发布的安全网。

</details>
