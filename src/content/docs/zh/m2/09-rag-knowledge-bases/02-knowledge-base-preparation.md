**一句话：** 知识库准备就是选定助手可以依据哪些文档作答，把它们转换成保留标题和表格的干净文本，并检查这些文档是否覆盖了真实用户会问的问题。

## 是什么

RAG 助手只能依据它的知识库作答，也就是它所检索的那些文档。知识库准备排在切分和向量化之前，所以这里的错误会被建进索引，之后助手还会自信地反复说出来。

打个比方，图书管理员给参考书架配书：他只上架官方版本，拒收自己无法担保的复印件。读者只能找到书架上有的东西。

它有四项工作。**来源选择**（source selection）列出每个来源及其负责人，并选定唯一的权威版本。**解析**（parsing）把文件（PDF、网页、Word）转换成文本加结构：标题、段落、表格。**清洗**（cleaning）去掉没有意义的内容。**覆盖检查**（coverage checking）确认这些文档能回答真实用户的问题。

## FDE 为什么需要

一所学院想用一份 SharePoint 导出文件和课程网站，做一个学生支持助手。原型引用的截止日期来自 `Academic_Policy_v4_DRAFT.docx`，而不是已发布的 v3，因为两个文件都被导入了。它漏掉了学费政策，那是一份没有文字层的扫描版 PDF。每个课程页面的文本块都以同一段导航菜单开头。一张被压平的学费表，把费用配到了错误的注册状态上。一个开放上传的文件夹也被建了索引，其中有一名学生写的便条，声称延期是自动批准的。

这些都不是提示词的问题。FDE 在向量化之前把它们全部修好：指定明确的负责人（教务处、财务处、各课程负责人）、只用经批准的来源、带 OCR（光学字符识别，用于读取页面图像）的版面感知解析器，以及对照原件做抽查。

## 核心概念

### 来源清单与可信导入

列出每个来源，写明负责人、权威版本和处理决定：纳入、排除或待询问。草稿、重复件和过期的副本一律不进。

任何人都能上传或编辑的内容都不可信。OWASP 将 Data and Model Poisoning（LLM05:2026）列为主要风险之一，并建议追踪数据来自哪里，把不可信来源与可信来源隔开。在研究环境中，PoisonedRAG（USENIX Security 2025）在数百万条文本中，为每个目标问题埋入五条文本，就能在约 90% 的情况下左右回答。因此，上传的内容要先放在隔离区，等指定的负责人批准后才能使用。

### 按来源类型解析

| 来源 | 问题 | 做法 |
|---|---|---|
| 文字版 PDF | 多栏内容混在一起，表格被压平 | 版面感知的解析器 |
| 扫描版 PDF | 没有文字层 | OCR 或视觉模型 |
| 网页 | 菜单、横幅、页脚 | 提取正文主体 |
| Word 文件 | 部分模型 API 不接受 `.docx` | 转换成 Markdown 或 PDF |

Docling（MIT 许可证，可在本地运行）和 Microsoft MarkItDown 这类转换工具，输出的 Markdown 会保留标题和表格。云端版面分析服务需要把文档上传出去，先确认客户是否允许。Claude 可以直接接收 PDF（页面图像加提取出的文本），视觉模型读扫描件的效果不错，但可能压缩表格版面，所以要抽查数字。

```text
纯文本提取：非全日制 全日制 1,250 2,400
版面感知：  | 非全日制 | 1,250 |
            | 全日制   | 2,400 |
```

### 清洗：去掉噪声，保留结构

去掉导航菜单、重复的页眉页脚、cookie 横幅、水印、换行处错误的断词连字符和乱码。保留标题、表格、列表和图片说明，因为切分和引用都依赖它们。把解析结果保存下来，这样既能检查，也能在不重新解析的情况下重新切分。

### 对照真实问题检查覆盖度

在收集文档的同时，从工单、FAQ 和搜索日志里收集真实问题。由领域专家把每个问题对应到能回答它的段落。对应不上的问题就是内容缺口，也就是 Barnett 等人（CAIN 2024）所列七个 RAG 失败点中的第一个。把它们交给内容负责人，而不是丢给提示词。

## 常见误区

- **“把整个共享盘都加载进去吧。文档越多，回答越好。”** 草稿和过期副本会与官方版本互相竞争，导致回答相互冲突。
- **“PDF 就是文字，随便哪个 PDF 库都能把字提取出来。”** 扫描版 PDF 是页面图像，需要 OCR 或视觉模型。
- **“清洗就是把一切都剥成纯文本。”** 切分和引用需要标题和表格；只去掉噪声。
- **“投毒是训练阶段的问题。我们的知识库只是一堆文档。”** OWASP 把 embedding 数据也算作投毒的目标；只要埋入几份文档，就能左右回答。

## 典型面试题

<details>
<summary>知识库准备包括哪些工作？为什么它要排在最前面？</summary>

选择经批准的权威来源，把它们解析成结构化文本，去掉样板内容，并对照真实问题检查覆盖度。下游的一切环节看到的都只有这些文本。

</details>

<details>
<summary>解析和清洗有什么区别？</summary>

解析把某种文件格式转成文本加结构，页面图像则用 OCR。清洗去掉菜单、重复的页脚等噪声，同时保留标题和表格。

</details>

<details>
<summary>客户交来一份 40 GB 的 SharePoint 导出文件。哪些内容该放进去？</summary>

从真实工单出发，让每个业务领域的负责人指定权威文档。排除草稿、归档和开放上传的文件夹。先对每种格式抽取一部分样本做解析，并对照原件检查。

</details>

<details>
<summary>助手引用的费用和官方表格对不上。你先看哪里？</summary>

先看检索到的文本块，再看它对应的解析结果。通常是被压平的表格丢了标签，或者导入了过期的费用表。修好解析器或移除那份副本，然后重新导入。

</details>
