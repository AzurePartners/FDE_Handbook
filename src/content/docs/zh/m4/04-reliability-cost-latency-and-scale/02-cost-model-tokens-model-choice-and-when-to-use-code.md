**一句话：** AI 功能按 token、按模型、按 API 调用、按存储和算力的用量花钱，所以控制成本就是衡量 token 用量、为任务匹配合适规模的模型、做缓存，并在确定性代码能胜任的地方改用更便宜的代码。

## 是什么

模型供应商按 **token** 计费（输入和输出分开算），模型越大，每个 token 越贵。除此之外，还有付费数据源、第三方 API 调用、存储和算力。一个功能如果每次调用都塞进海量上下文，拿最高档的模型去做琐碎的任务，或者在几行代码就能搞定的地方去调用模型，成本可能比必要的高出几个数量级。成本模型就是这样一组可调的杠杆：衡量 token，裁剪提示词和上下文，限制输出长度，做缓存，为每个任务匹配合适规模的模型，凡是不需要模型的地方都优先用确定性代码。

## FDE 为什么需要

和大多数软件不同，AI 功能的成本是可变的，会随用量增长；一个演示只花几美分，到了客户的规模上可能要花几千美元。一个 FDE 常常要让单位经济模型成立，并且能估算单次请求成本，这样你才能承诺一个在生产环境中花得起的功能，而不只是演示时令人惊艳的功能。

## 核心概念

- **token 用量核算：** 每个请求的输入 token 加输出 token，是账单的核心。
- **为任务匹配合适规模的模型：** 分类和简单任务用小而便宜的模型；只有质量要求高时才用规模大的模型。
- **能用代码就不用模型：** 确定性逻辑便宜得多，结果也精确，别花钱让模型去做加法。
- **裁剪与限制：** 只发送需要的上下文；限制输出长度。
- **缓存与批处理：** 复用结果；合并调用（与可靠性那一页相关）。
- **预算与告警：** 按功能或按客户设上限，并设置支出告警。

## 常见误区

- **“所有任务都用最好的模型。”** 大多数任务用更小、便宜得多的模型就能满足；规模大的模型留给难处理的情况。
- **“上下文越多，质量越高。”** 超出相关内容的部分会增加成本，还可能稀释答案。
- **“成本是固定的。”** 它随 token 和用量增长；没有衡量和上限，它会悄悄涨上去。

## 典型面试题

<details>
<summary>什么决定了 LLM 功能的成本，你如何控制它？</summary>

成本按 token 计（输入和输出），随模型大小和调用量增长，再加上付费数据、API 调用、存储和算力。我的控制办法是：裁剪上下文并限制输出，做缓存和批处理，按任务为模型匹配合适的规模，凡是确定性代码够用的地方就用代码，并设置按客户的预算和支出告警。

</details>

<details>
<summary>什么时候该用代码而不是模型调用来实现逻辑？</summary>

只要任务是确定性的、要求精确的，比如计算、查询、格式化、执行规则，就该用代码。代码更便宜、更快，而且每次都正确；模型调用要花 token，还可能出错。把模型留给只有它能处理的模糊部分（语言、判断）。

</details>
