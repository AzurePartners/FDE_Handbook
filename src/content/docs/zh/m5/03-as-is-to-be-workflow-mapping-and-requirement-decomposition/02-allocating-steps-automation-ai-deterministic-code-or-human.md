**一句话：** 工作流梳理完之后，每个步骤最适合交给四种处理方式之一：简单自动化、AI 模型、确定性代码或人工，而为每个步骤匹配合适的方式，是设计 AI 辅助工作流的核心。

## 是什么

并不是每个步骤都该用同一种方式来做。有这四种选择：

- **简单自动化：** 机械、不含规则逻辑的流转（触发、复制、通知）。
- **AI / 模型：** 需要语言理解、判断、分类或起草的步骤。
- **确定性代码：** 必须精确、基于规则的步骤（计算、校验、强制执行限制）。
- **人工：** 需要有人负责、需要做高风险判断或需要审批的步骤。

分配步骤，就是对着工作流图逐个步骤过一遍，把每个步骤分给最合适的处理方式：模糊的、语言类的工作留给模型，精确的、后果重大的工作放进代码，不可逆的、高风险的决策交给人。

## FDE 为什么需要

一上来就想“全部用 AI 来做”，做出的系统会在需要精确的地方不可靠，又在简单自动化就够用的地方过度设计。反过来，把一切都写死在代码里，则浪费了模型独有的长处。正确地分配每个步骤，即模型判断、代码执行、高风险的由人审批，才能让 AI 辅助的工作流既有能力又安全。这与第 5 课的架构决策直接相关。

## 核心概念

| 步骤类型 | 最适合的处理方式 |
| --- | --- |
| 机械流转 / 触发 | 简单自动化 |
| 语言、判断、分类 | AI / 模型 |
| 精确计算、规则、资金 | 确定性代码 |
| 高风险 / 不可逆 / 需要有人负责 | 人工 |

- **模型判断，代码执行：** 把对后果的决定权留在代码里。
- **不可逆的交给人：** 给高风险步骤加上人工 gate（与 HITL / 权限相关）。

## 常见误区

- **“每个步骤都用 AI。”** 精确的、后果重大的步骤属于代码；有些步骤只需要简单自动化；有风险的步骤需要人。
- **“全部写成代码，模型不可靠。”** 这样就浪费了模型在语言和判断上的长处。
- **“怎么分配是显而易见的。”** 这是一项需要深思熟虑的设计决策，会对可靠性和安全产生实实在在的影响。

## 典型面试题

<details>
<summary>你怎么决定每个工作流步骤该交给谁处理？</summary>

我给每个步骤匹配最合适的处理方式：机械流转用简单自动化，语言、判断、分类用 AI 模型，任何精确或后果重大的事（计算、规则、资金）用确定性代码，高风险或不可逆的决策交给人。原则是模型判断，代码执行，高风险的由人审批。

</details>

<details>
<summary>有一个步骤要计算客户的退款金额，该由谁处理？</summary>

确定性代码，因为这一步必须精确且经过授权；模型可以理解客户的请求并提出退款建议，但金额和政策限额由代码强制执行，超过阈值就由人审批。让概率性的模型对资金拥有最终决定权是不安全的。

</details>
