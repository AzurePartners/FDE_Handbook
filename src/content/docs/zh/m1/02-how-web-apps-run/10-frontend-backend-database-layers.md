**一句话：** Web 应用不是一个程序，而是一组运行在不同地方的独立组件，它们来回传递消息，共同产出一个结果。

## 是什么

你打开一个 Web 应用时，看到的只是一条组件链露出水面的尖端。链上每个组件运行在不同的地方，各自只做一件事。浏览器负责绘制页面、响应你的点击。前端程序（通常是 JavaScript）决定显示什么、何时去请求数据。API 是后端对外开放的入口，其他程序通过它向后端要东西。后端掌握真正的逻辑：它检查请求、决定怎么处理，并与数据库打交道，有时还会调用其他公司的服务。数据库负责存储信息，让数据在程序停止运行后依然保留。

日常生活中的类比是餐厅。你（浏览器）看菜单（前端），告诉服务员你要什么，也就是向 API 发请求。服务员不下厨，他把你的点单送到后厨（后端）；后厨去查食材库（数据库），有时还要给供应商（外部服务）打电话。

每个组件都是独立运行的程序，往往在不同的机器上，它们只通过网络上定义好的消息了解彼此。这种分离是刻意设计的：每个组件都可以单独构建、部署和修复。

## FDE 为什么需要

客户说“应用很慢”或“应用坏了”，却说不出更多细节。你的第一项工作是找出是哪个组件出了问题：页面渲染、前端根本没发出请求、后端逻辑太慢、数据库被锁，还是外部服务挂了。脑子里没有这张组件地图，你只能瞎猜。有了这张图，一个精准的问题——“Network 面板里显示了什么？”——就能把问题缩小到一个方框里。

## 核心概念

### 各组件，按顺序

- **浏览器**：请求页面，并渲染收到的内容。
- **前端**：在浏览器内运行、构建界面的代码。
- **API**：后端公开的契约，包括具体的 URL、方法和数据结构。
- **后端**：运行业务逻辑、检查输入的服务端程序。
- **数据库**：在请求之间存储数据的地方。
- **外部服务**：通过互联网访问的其他公司的系统。

### 一张简单的架构图

```
+-----------+        HTTP request         +-----------+
|  Browser  |  ------------------------->  |    API    |
| (frontend)|                              |           |
|           |  <-------------------------  |           |
+-----------+        HTTP response         +-----------+
                                                  |
                                                  v
                                          +---------------+
                                          |   Backend     |
                                          |   logic       |
                                          +---------------+
                                             |          |
                                             v          v
                                     +----------+  +---------------+
                                     | Database |  |   External    |
                                     |          |  |   services    |
                                     +----------+  +---------------+
```

用户点击按钮，前端向 API 发送请求，后端逻辑读写数据库，可能还会调用外部服务，然后响应沿同一条路径反向传回。

## 常见误区

- **“前端和后端是同一个程序。”** 它们是不同的程序，只是通常由同一个团队开发。它们只通过请求和响应通信。
- **“API 就是后端。”** API 是入口：其他程序访问后端时使用的 URL 和规则。后端是入口背后的一切。
- **“页面能打开，整个系统就是好的。”** 页面可能是从缓存文件加载的，而此时 API、数据库或某个外部服务可能已经完全挂了。

## 典型面试题

<details>
<summary>画出或描述一个典型 Web 应用的架构。</summary>

浏览器和前端在用户的设备上，通过 HTTP 与 API 通信。API 把请求交给后端逻辑，后端逻辑读写数据库，也可能调用外部服务。响应沿同一条链路反向传回。

</details>

<details>
<summary>客户说他们的应用很慢。你从哪里开始查？</summary>

打开浏览器的 Network 面板，看每个请求的耗时。如果请求本身耗时很长，问题多半在后端、数据库或外部服务。如果请求很快，页面却仍然感觉慢，问题多半在前端渲染。

</details>

<details>
<summary>为什么后端和数据库要作为两个独立的程序运行，而不是合成一个？</summary>

分开之后，每个组件都能独立扩展、独立出故障、独立替换。后端重启不会丢失已存储的数据，因为数据库自己在单独运行。

</details>
