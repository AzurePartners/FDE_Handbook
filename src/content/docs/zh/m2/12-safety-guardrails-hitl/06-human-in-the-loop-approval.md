**一句话：** 人在回路（HITL）审批是一个检查点：代码把某个已获许可的具体 AI 操作暂停下来，等有人确认后才放行，只用于代价高昂或难以撤销的操作。

## 是什么

有工具的助手可以采取行动：退一笔款、发一封邮件、取消一项服务。人在回路审批让其中一部分操作先等一个人点头。（这个说法也用来指人工标注训练数据；这里指的是运行时的审批。）

一个靠谱的承包商买钉子不用问你，但拆墙之前会请你签字。要是每颗钉子都来问你，你很快就会不看就签，连拆错了墙也照签不误。

准确地说，操作 gate 决定这个用户到底能不能做这件事；审批则决定在已获许可的操作里，哪些仍然需要有人把关。OpenAI 的 agent 指南按写入权限、可逆性、权限和资金影响给工具评级，让高风险的工具处于人工监督之下，“直到对 agent 可靠性的信心逐步建立”。

## FDE 为什么需要

为了显得安全，一家互联网服务商的客服助手把每一个写操作都送去审批。几周之内，组长们每天要面对约 400 个请求，大多是 5 美元的账单抵扣，每个都只花两秒就批准了，凭的是一张写着“按客户要求抵扣费用”的卡片。其中一张卡片的文字与其他的一模一样，实际却是给一个不属于该客户的账号抵扣 900 美元，照样被批准了。

FDE 和客户一起给每个工具评了级，小额抵扣改为自动执行并每天抽样检查，让操作 gate 拦住他人的账号，并重做了卡片。队列降到每天约 30 个，少到能认真读完。（示例场景。）

## 核心概念

### 按影响和可逆性给操作评级

| 档位 | 示例 | 默认做法 |
|---|---|---|
| 只读查询 | 查看账单 | 自动执行，记录日志 |
| 可逆的写操作 | 添加备注、小额抵扣 | 限额内自动执行，持续监控 |
| 代价高或不可逆 | 大额退款、付款、删除 | 先由指名的审批人批准 |
| 绝不自动化 | 修改银行账户信息 | 助手起草，由员工执行 |

阈值决定工具落在哪一档：15 美元的抵扣自动执行，150 美元的就要等，具体限额由客户设定。主流的 agent 工具包（OpenAI、Anthropic、Google、Microsoft、LangChain）都内置了这种暂停机制，其中多数支持按调用的参数来写规则。

### 在代码中强制审批

像“大额退款前先询问”这样的一行提示词不算控制措施：模型可能判断失误，也可能被注入的文本操纵。要由代码在产生任何副作用之前、对每一次调用做决定，批量调用里的每一次也不例外：

```python
def run_tool(call, user):
    gate.check(call, user)                # 这个操作本身是否允许？
    if needs_approval(call):              # 按工具名和参数判断的规则
        rec = approvals.get(call.id)
        if rec is None:
            return approvals.request(call)    # 暂停，展示卡片
        if rec.decision != "approve" or rec.args != call.args:
            return rejected(call, rec)
    return tools.run(call, idempotency_key=call.id)
```

幂等键让双击变得无害。卡片上会显示账户持有人、金额、客户的原话、政策条款、近期的抵扣记录，以及这个操作能否撤销。每个决定都要记录日志（谁、何时、批了什么、为什么），超过期限仍无人答复的请求按拒绝处理。

### 审批疲劳

Anthropic 在 2026 年 3 月报告说，Claude Code 用户会批准 93% 的权限提示，并警告存在审批疲劳，即“人们不再认真留意自己批准的是什么”。要少问几次，并跟踪批准率和做出决定所用的时间。让模型来当审批人也替代不了人：Anthropic 的 auto mode 分类器漏掉了 17% 真实存在的“过度积极”操作。

### 人在回路中与人在回路上

人在回路中，人点头之前什么都不会发生。人在回路上（human-on-the-loop），系统先行动，人在一旁盯着，随时可以叫停或撤销，就像驾校教练的脚悬在副刹车上方。Anthropic 发现，经验丰富的 Claude Code 用户自动批准得更多，但中途打断得也更多。罕见、影响大的操作用人在回路中，高频、可逆的操作用人在回路上。

## 常见误区

- **“最安全的设计是每个操作都由人批准。”** 这样一来，人会凭习惯去批准。把审批留给少数真正重要的操作。
- **“只要有人在回路中，系统就是安全的。”** 人会过度信任语气笃定的机器输出（自动化偏见，automation bias），含糊的卡片则会让审批沦为橡皮图章。
- **“只要经理批准了，这个操作就是允许的。”** 审批绝不会扩大权限，也不能突破硬性上限。
- **“标着只读的工具一定安全。”** 像 `readOnlyHint` 这样的标签只是提示，而且有些读取操作会把数据发到公司之外。

## 典型面试题

<details>
<summary>什么是人在回路审批？什么时候必须用？</summary>

在代码执行某个已获许可的具体操作之前，由一个人来确认。对代价高或不可逆的操作，比如大额退款、付款和删除，它是必须的；读取和代价低、可撤销的写操作自动执行并记录日志。

</details>

<details>
<summary>人在回路和人在回路上有什么区别？</summary>

人在回路中，操作要等一声“同意”，适合罕见、影响大的操作。人在回路上，系统先行动，人负责监控，必要时可以干预，适合高频、可逆的操作。

</details>

<details>
<summary>审批人在三秒内批准了 99% 的请求。你会怎么做？</summary>

把它当作审批疲劳，或者阈值设得太低的信号。低价值且可逆的操作改为自动执行并加监控，在卡片上展示确切的操作和证据，每周跟踪批准率。

</details>

<details>
<summary>一笔已批准的 50 美元退款实际执行成了 500 美元，另一笔则执行了两次。哪里出了问题？</summary>

审批没有绑定到确切的参数，执行也不是幂等的。只执行参数与审批一致的那条已存储调用，并带上幂等键。

</details>
